# Fixed cgroup containment probe on the ARM VM

The uninstalled `gauntlet-cgroup-containment-shadow` is a Root-only Linux ARM64 diagnostic. Its code fixes the cgroup name under `/sys/fs/cgroup/system.slice`, the command (`/bin/sh -c '/usr/bin/sleep 5 & wait'`), and the memory, PID and CPU ceilings. It accepts no job, candidate, path or command argument. The child enters the newly created cgroup in `pre_exec`, before the shell can run. The probe waits until at least two tasks are observed, writes `1` to `cgroup.kill`, reaps the shell, requires the existing recursive drain observer to see an empty subtree, and removes the exact cgroup. Every successful response states `benchmark_executed: false` and `execution_eligible: false`.

On 2026-10-20, the stripped ARM64 diagnostic had SHA-256 `ead4598ca0a40dfe9e366b7c92630047a3a7a9f7471ca9f2d9b1be8e3baac7ec` on both the Mac and the idle `hol-beta-bootstrap-20261016-004` VM. An unprivileged invocation exited 2 because Root is required. The Root invocation reported `observed_tasks: 2`, `recursive_kill_written: true`, `drained_observed: true`, and `cgroup_removed: true`. A separate check found the fixed cgroup absent afterward. Both temporary probe copies were removed from the VM; free disk space was 8,669,736,960 bytes after cleanup. Linux ARM64 Clippy passed with warnings denied. The [Linux cgroup-v2 specification](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html) defines `cgroup.kill` as killing the cgroup and descendants, and `cgroup.events` `populated` as recursive; the probe verifies the resulting state rather than assuming the write was sufficient.

This is a containment mechanism proof for fixed inert processes only. It does not place the product cell, Podman builder, Python controller, or model-backed benchmark in this cgroup. It does not bind a started marker, active-run deadline, trusted controller install, report or terminal receipt to the killed processes. Failure paths retain an uncertain or identity-changed group for operator inspection and never report a successful terminal benchmark. The Linux worker exit remains open until an actual source-pinned job runs under exclusive cgroup ownership and its descendants are observed drained before terminal publication.
