# Rust job-owned product-cell slice boundary

The current Python VM worker launches the deterministic controller with a fixed environment. Its product-cell supervisor still defaults to `system.slice`. A future Rust worker can instead set `HOL_GAUNTLET_RUST_JOB_SLICE=holgauntletrust<16-lowercase-hex-job-id>.slice` in that controller's environment. The supervisor validates the complete value before touching product inputs and passes `--slice=<value>` to `systemd-run`; it observes each cell under `/sys/fs/cgroup/<value>/<unit>`. Rust derives the value only from the parsed `WorkerRequest.job_id`, while its frozen Python-compatible launch vector remains unchanged. The [systemd-run manual](https://www.freedesktop.org/software/systemd/man/255/systemd-run.html) specifies that `--slice` places a transient service in the named slice.

The Rust terminal writer now requires that exact job slice to be absent before it can write a terminal receipt under the active lease. It opens `/sys/fs/cgroup` as a Root-owned no-symlink directory and rejects any existing slice, including an empty directory or symlink, with an identity recheck. This is a **necessary** cleanup condition only. The controller must first be stopped and reaped so it cannot create another unit after the check. The Rust dispatcher, systemd slice stop, controller process binding, product-cell inventory and independent whole-job cleanup proof remain open.
