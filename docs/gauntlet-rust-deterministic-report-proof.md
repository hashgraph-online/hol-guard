# Fixed deterministic report custody and identity

The Rust `gauntlet-evidence` reader now opens only `/var/lib/hol-gauntlet/outputs/<16-hex-job>/report/result.json`. It requires Linux Root; Root-owned non-writable path ancestry; private 0700 output, job and report directories; a regular single-link 0600 result file; bounded bytes; no symlinks; and stable descriptor/path metadata across two reads. Its data validator compares the raw report with outside source and config digests and process exit code, requires the deterministic profile and known zero-model usage, and reports the controller's status as a **producer claim**. The diagnostic CLI also requires an outside raw-report SHA-256. It never treats `status: passed` or a cell's `passed` field as an independently recomputed Guard verdict; every result says `execution_eligible: false`.

It observed six cells and a producer claim of `passed`, with `control_verdict_recomputed: false`. The unprivileged call, wrong report digest, wrong config digest and wrong exit code all returned exit 2. These outside pins were read from the same retained VM and are test inputs, not an independently reviewed controller or source generation. The historical report came from the Python worker, not a new Rust-controlled run. The reader does not authenticate native Pre/Post, service effects, kernel isolation, six role outcomes, feature audit, model usage from provider deltas, or cleanup. A future Rust dispatcher can use this bounded reader after containing and reaping its child, but must independently recompute the verdict before any success receipt or PR gate claim.
