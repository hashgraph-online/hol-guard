# Rust host/VM wire proof (2026-10-20)

This proof advances two separate boundaries on draft PR #5402. It does **not** run a benchmark or make a worker eligible to qualify a build.

The macOS host crate now owns a caller-launched child during the prepared/ack exchange. `HostControllerKeyPinJournal::accept_prepared_child` reads at most one 1-KiB prepared frame, checks the planned source/job/deployment/generation tuple, fsyncs the one-use host key record, and only then writes the acknowledgement. A refusal kills and asynchronously reaps the host child. It reports whether a pin exists or is uncertain; an acknowledged job remains consumed even if the host transport later times out. `HostPreparedProcess::wait_bounded` bounds only the host process and never claims that killing `limactl` stopped a guest descendant. This adapter still requires an independently reviewed Lima executable, VM, guest worker, controller source and deployment before a live dispatch.

The host also has `VmRustShadowPlan`, which freezes a read-only `progress` request and derives the sole guest executable path from a 64-hex outside binary hash. It binds one canonical response to the request, outside worker-generation pin and deployment pin. It refuses extra stdout, malformed frames, wrong identity and failed transport. The plan explicitly reports `binary_pin_verified: false` and `execution_eligible: false`; a path containing a hash is not executable attestation. `gauntlet-host-shadow-rust-worker` uses compiled public VM defaults and never selects `run` or opens the private Python observer config.

On native ARM64 Docker, `cargo test --locked -p gauntlet-host-state` passed the full host crate, including three new child-process tests and three fixed-Lima-plan tests. `cargo clippy --locked -p gauntlet-host-state --all-targets -- -D warnings` and workspace format checks passed. The earlier pushed documentation head `df0034b9` completed repository product CI [run 39552093120](https://github.com/hashgraph-online/hol-guard/actions/runs/39552093120) successfully and all three isolated Rust checks passed; this new source still requires its own pushed-head CI.

Code commit `4fafbf97` extended that path to the complete **request → prepared → acknowledgement** sequence. The Mac host now sends one canonical, bounded `hol-gauntlet-worker-request.v1` `run` frame for the planned source/job/deployment before accepting a prepared frame; all three messages share a 60-second handoff deadline. The ARM guest uses the same bounded worker pipe reader and refuses noncanonical frames, other actions and requests that differ from its outside tuple before generating its ephemeral values. Local process and worker tests cover the wrong job, noncanonical bytes, `progress` instead of `run`, replay and timeout. The new 900,880-byte Root-owned 0755 installed guest diagnostic at `/opt/hol-gauntlet/rust-prelaunch-wire-shadow-41b292ddc500b79f4043a11de3b707ee8101940c7271fd295185215179f65391` matched SHA-256 `41b292ddc500b79f4043a11de3b707ee8101940c7271fd295185215179f65391` in the ARM build container, Mac copy, guest copy and final installed file; transfer copies were removed.

No `abcdef0123456789.started.json` appeared in the Rust VM worker state. Native macOS host tests, four ARM worker pipe tests, ARM release build, workspace Rustfmt and warnings-denied Clippy passed. This remains an inert protocol test: the `run` verb did not reserve or execute a benchmark.

The next live execution step must authenticate the exact host and guest binaries and Root controller generation from a reviewed base, bind a fresh deployment and source archive to a one-time worker lease, repeat this prepared/ack exchange with durable guest marker and sidecar custody, run the controller in the job cgroup and product slice, and authenticate its terminal report and six controls before any verdict. An interruption after acknowledgement must remain unknown until independent guest reconciliation. The model-backed campaign and provider accounting exits remain separate in the [execution checklist](gauntlet-rust-execution-checklist.md).
