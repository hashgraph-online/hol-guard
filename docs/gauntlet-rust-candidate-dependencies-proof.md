# Inert candidate dependency proof

The Rust `gauntlet-candidate-dependencies-shadow` diagnostic checks a cloned, **unadmitted** v3.48.0 prefix without importing the candidate or installing packages. It holds the Rust and Python worker locks, verifies the captured release source and candidate archive against outside SHA-256 pins, requires an inactive builder, and inventories the whole Root-owned prefix before and after the metadata read. It opens `.dist-info/METADATA` through no-symlink, descriptor-relative paths; regular-file ownership, mode, size, link count and descriptor identity are checked. The 128-KiB metadata bound allows unrelated long folded headers seen in a real installed package, while identity fields and `Requires-Dist` declarations have smaller bounds.

The pure Rust evaluator parses PEP 508 declarations and PEP 440 versions, evaluates markers with no selected extra, and refuses malformed declarations, active direct URLs, missing baseline distributions and incompatible versions. Its interpreter version is an outside observation (`3.12.3`), not an authenticated executable pin. The diagnostic reports `execution_eligible:false`, `candidate_executed:false`, `conformance_completed:false` and `artifact_admitted:false`.

On the 2-vCPU/16-GiB ARM VM, the final static binary was independently SHA-matched at `c20f3b37ec194c65423bd6ac5377be0d8a26f037a45629b4f8778979b338bf41` after Root:Root mode-0500 installation with one link. The live check used release job `aaabefe820493283`, source commit `3864097f2e4fe623e403c1a948d9882f34c78690`, source-archive SHA-256 `5d3eeff80bedd07042a28ffdf5d0192500669b238384ca71f7a3f8631f9382be`, candidate archive SHA-256 `a427dad674c9cd0b37ee14b1d72483de6838b1e8fbfe95b224ecd5abd0da3944`, prefix tree SHA-256 `b25a0f04235238e3cd5b64df04dc4fa8fd7f82b2aca7142d46336ca63330fa1e`, and native SHA-256 `f92d6c007ddbf49ef00d547a72a6ba8dfacf6f98db2150177c2baf41cb944311`. It also checked the installed runtime manifest's source, package version and native digest through bounded no-symlink paths. Wrong prefix and native digests refused. The first exact-pins attempt exposed an overly tight 4-KiB limit on an unrelated folded header in `sigstore_rekor_types`; after a targeted parser correction and unit test, a separately installed binary completed the read-only check.

Rust found 62 installed distributions and 22 candidate requirements: 12 active requirements satisfied by the prefix and 10 inactive requirements. The active names were `cryptography`, `idna`, `jsonschema`, `keyring`, `mcp`, `packaging`, `pyyaml`, `regex`, `requests`, `rich`, `tomlkit` and `typing-extensions`. The pinned Python `stage_candidate.py` dependency loop, invoked separately with `/usr/bin/python3 -I` on the same prefix, returned **the same counts, names and accepted versions**. Local Rust tests for marker filtering, refused dependencies and the real folded-header case passed; ARM64 warnings-denied Clippy passed.

This proves a read-only dependency and installed Guard identity check for one release wheel and one installed baseline. It does not authenticate the Python interpreter or provenance of every baseline distribution, produce a candidate config, run conformance or product controls, invoke feature audits, or make the prefix eligible for execution. Those remain open in the migration checklist.
