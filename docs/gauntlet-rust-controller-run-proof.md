# Internal Rust controller lifecycle proof

Lifecycle code pins: `6f67141688a57b3415ef32eed56d914c77e93408`, with explicit cancellation added at `7ad030a6159b25c7a729c343c741e90828dba4ac`, on draft PR #5402. The changed worker code is `ci/gauntlet-rs/crates/gauntlet-worker-state/src/controller_run.rs`, with the launch-error distinction in `controller_exec.rs`. This proof concerns an internal, unwired function. It is not a benchmark run or a terminal receipt.

`run_prepared_controller_ineligible` refuses a pre-set cancellation flag, starts a Linux `CLOCK_BOOTTIME` deadline from a reviewed timeout argument, verifies the exclusive Root worker lease, creates the job-ID-derived capped controller cgroup, and calls the existing descriptor-bound fixed controller launcher. After launch it samples the child through `/proc` and `pidfd`, writes the durable running marker under the same lease, and checks the lease and cancellation flag while waiting for exit or deadline. Every ordinary return after cgroup creation attempts recursive kill, bounded direct-child reap, cgroup drain/removal, and—only when this invocation spawned a child—stop plus independent absence observation of the exact job product-cell slice. A prelaunch refusal cannot stop an older run's product slice. Failed identity, lease, deadline, cancellation, wait, or cleanup evidence leaves the one-use job unresolved. No OS signal handler is wired to the flag yet.

On native Linux ARM64 in the pinned `rust:1.88.0-slim-bookworm` image (`sha256:38bc5a86d998772d4aec2348656ed21438d20fcdce2795b56ca434cf21430d89`), all three child-wait tests passed. They cover normal exit, a one-second `CLOCK_BOOTTIME` expiry with explicit child reap, immediate owner-loss refusal, and cancellation refusal. ARM64 `cargo clippy -p gauntlet-worker-state --all-targets --locked -- -D warnings` passed. An earlier full worker library run in that container passed 25/28; three existing live-cgroup tests failed because Docker exposes this container at cgroup `/`, which those tests intentionally reject.

The final test executable, SHA-256 `9d2c4b083862b4632f2be0edfc6056e2be11106fbe110c68218b4b222071f19e`, was copied to the running 2-vCPU/16-GiB ARM VM `hol-beta-bootstrap-20261016-004`. The VM recomputed that SHA, and the unprivileged test run passed **29/29**, including the three live-cgroup tests. The new lifecycle function has not executed a controller in the retained VM. Its cross-component cleanup ordering has been statically reviewed and compiled, not proven under a live product cell.

This code does not authenticate the outside source/installer pins, dispatch from a public worker request, handle OS termination signals, read or score a Guard report, write a terminal receipt, prove interruption recovery, or run model inference. A future production worker must exercise actual controller and product-cell processes under the lease, independently verify the six controls and cleanup, and retain unknown state on any surviving or uncertain unit. The Python worker remains authoritative and the PR gate remains passive.
