# Initial CIGAR selection

The existing `prepare_switch` / `commit` operator contract now supports a disabled profile with no selected runtime and no saved data. It uses the shared bounded worker, lifecycle lease and job namespace. It does not invent a previous SDK, data generation, last-good selection or app grant.

Preparation captures the exact local/managed preferences, current native generation, authenticated empty-data proof and measured target installation. A temporary private target passes the same SDK checks as activation. Ready remains cancellable and carries `operation=select`, `initial_selection=true`, `keeps_disabled=true` and `reconnect_required=false`. Status reads start no SDK. A commit is accepted only by the matching live coordinator, with its original source mode, runtime ID and prepared-data identity.

The first-selection marker is authenticated separately from ordinary switch records. Under the short native writer lock it precedes configuration publication and the normal selected SDK/data record. The normal record has revision 1, the actual target and no previous selection. The empty-data proof binds the protected profile directory identity as well as saved slots, generations and native ownership rows; another profile or a replaced directory cannot reuse it. Existing slots or generations require a later explicit data-choice flow and remain untouched.

The target is remeasured and closed before the short commit lane. Publication advances the native generation while both enablement values stay false, with no serving actor. Uncertain configuration/first-record acknowledgements are observed against the sealed target, exact settings and empty-data proof; SDK initialization is not replayed. A pending marker blocks ordinary activation. Cancelled unpublished intent and an already Healthy target support explicit reconciliation. Healthy completion repair changes only metadata and starts no SDK. For earlier committed target phases, [bounded initial recovery](CIGAR_INITIAL_RECOVERY.md) now performs explicit temporary SDK re-verification before completing records, while keeping the profile disabled.

Enabling the selected runtime is a separate ordinary settings action. Activation rechecks the installation; file scopes and note access require fresh explicit grants. A legacy saved-data layout does not identify the SDK as an enrolled candidate: test summaries now measure the catalog-selected producer before exporting reviewed notes.
