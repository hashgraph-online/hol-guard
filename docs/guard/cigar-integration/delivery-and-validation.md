## First-release capability spike

Before building the UI, run a small installed-artifact experiment:

1. Install an approved exact candidate in an isolated 3.14 environment on a qualified target.
2. Probe interpreter/build identity and package/worker metadata through the proposed supervisor.
3. Start a graph, admit synthetic native-policy and receipt facts, create two narrow views, and compile within the proposed limits.
4. Change a readable source and prove the old context is stale. Change an outside-scope source and verify the SDK's documented preservation behavior.
5. Disable assistance while compile is active. Prove bounded shutdown and that an unrelated native hook and an already supported approval still complete.
6. Measure the bridge plus all child workers, including cold verification, memory, descriptors and serialization cost.

If these bounds are poor, evaluate a separate native host before embedding CIGAR in the resident. Any direct-native route must retain the user-required Python availability rule and the same opt-in, privacy and release checks.
