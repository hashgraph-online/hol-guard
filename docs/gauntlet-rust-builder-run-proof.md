# Passive Rust builder run plan

The pinned Python VM supervisor in `ci/gauntlet/control_plane/vm_build.py` (SHA-256 `48f5525cc04cfd0dc3ba14cee03849d4a2870e24ba23e118be2142a525ed3a98`) constructs a Podman run command after its separate source capture, image build, AppArmor profile installation and lease checks. `freeze_builder_run_v1.py` calls that Python function without starting a process and stores four actual-path argv vectors: v3.48 at 12 GiB, v3.49 at 16 GiB, a local 3.50 alpha, and a retained-artifact retest. It also stores the Python refusal for zero, excessive, boolean and fractional memory.

The Rust `fixed_builder_run_plan` matches all four command vectors byte for byte. It accepts only a SHA-256 image ID, 16-hex job ID, 40-hex source commit, 64-hex archive digest, the two allowed release tags or matching local tag/version, a 1–128 GiB integer memory limit and an optional local-only retained build ID. Extra fields and arbitrary command, image, path or tag selectors refuse. The fixed vector retains UID/GID 65532, all-capability drop, no-new-privileges, a per-job AppArmor profile, equal memory/swap bounds, two CPUs, 512 PIDs, `slirp4netns`, private IPC and fixed read-only source volume. Its result always reports `execution_eligible: false`.

Two local Rust tests passed against the source-hash-pinned Python fixture and negative identities. The isolated Linux ARM64 CI job now runs those parity tests along with the archive-reader tests. This is an argument-plan proof only. It does not authenticate the image, profile, source archive or mounted paths; install/remove AppArmor; verify `slirp4netns`; launch Podman; capture a wheel; prove cleanup; or reconcile a failed build. The Python builder remains authoritative.
