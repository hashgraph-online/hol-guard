# Isolated host pin and keyed-terminal composition

The Rust host crate now has an opt-in `HostControllerKeyPinJournal` separate from Python's live observer state. A caller must create a private host directory and open it through no-symlink descriptors. For one job ID, the journal exclusively writes a canonical `hol-gauntlet-host-controller-key-pin.v1` record with mode 0600 and `fsync`s both file and directory. The record binds job ID, source SHA, deployment digest, worker generation, started-marker SHA-256, controller-key sidecar SHA-256 and public key. A partial record consumes that job ID; a later call cannot overwrite it. The restarted reader checks owner, mode, link count, stable file metadata, canonical bytes, exact fields and the held directory's visible identity. No Python job, lock, queue or dashboard state is modified.

The data-only host reader composes the retained record with bounded canonical `hol-gauntlet-worker-terminal.v2` bytes and exact canonical report bytes. It requires all host-pinned identities and both marker digests to match, verifies the terminal's report SHA-256 against the supplied bytes, and checks basic process/exit/status shape. Its observation carries `execution_eligible: false` and calls terminal status `producer_status`: the terminal's `passed` field is not an independent Guard verdict. The existing v1 worker response still projects keyed terminal state as `unknown`.

Eight isolated host tests passed: exclusive durable write and restart, malformed/partial record and replay refusal, symlink and replaced-directory refusal, keyed-terminal/report binding with changed started-marker, sidecar, public-key, report, schema and impossible-success cases, [prelaunch acknowledgement ordering](gauntlet-rust-prelaunch-handoff-proof.md) with four planned-identity mismatches, plus bounded local-pipe success, timeout, oversize and lost-ack behavior. The complete host crate passed five unit and 42 integration tests in the pinned native ARM64 Rust 1.88.0 container; warnings-denied workspace Clippy and formatting passed. The pin journal, terminal reader and test source hashes are SHA-256 `44f2499a66e6f8ce240053fcc0fad2ca7caae7f7ed58603bcb6cfad04418ae0a`, `4ed5ba3eb9d6a7a258c65313281ccb867e9e65118bb7e1ac2c572770b0cd3aa8` and `39268ba8f63563a131fc011d993dedb7dccafdbf6f0bc7a9709f10dcb953fdb6`, respectively.

This is a library and synthetic-file proof. The caller has not yet received a Root worker's pin over a reviewed transport, persisted it before acknowledging controller launch, or reconciled a fresh VM terminal after crash/restart. A hash read only from the VM after execution is not an outside prelaunch anchor. The host record must live outside the VM's writable mounts. Signed control records, kernel/product observations, real model inference and independent verdict scoring remain open. The PR stays draft and the gate remains passive.
