# Rust read-only host job inventory proof

`gauntlet-host-state::read_private_jobs` now opens the existing Python host state without taking the observer lease. It walks the absolute directory path through no-symlink descriptors, requires the state root, `private`, and `jobs` directories to be owned by the current user and private, and opens only 16-lowercase-hex `.json` records with owner-only file permissions and one hard link. Each record is bounded to 1 MiB; the scan is bounded to 4,096 jobs and 32 MiB total. It checks descriptor/path metadata before and after each read and resamples the directory names. Any malformed, unsafe, oversized, or visibly changed record makes the whole read unavailable. It returns historical data only and cannot acquire the Python lock, publish status, dispatch a VM job, or approve admission.

Three synthetic integration tests passed locally on 2026-10-20. They cover an archived `unknown` job still blocking queue selection, file-mode and identity refusals, symlink refusal, an unfinished filename and an oversized record. The isolated Rust workflow runs these tests on native Linux ARM64. No intentional concurrent rewrite or interrupted observer recovery has been proven yet.

The uninstalled `gauntlet-host-shadow` diagnostic read the retained Mac state at `workflow-benchmark-implementation/.gauntlet-ops` on 2026-10-20 at about 19:43 UTC. It emitted only counts: 116 jobs, 90 archived, and states `archived:77`, `build-failed:11`, `diagnostic-passed:3`, `passed:20`, `superseded:5`; no `unknown` job was present. An independent Python read over the same 116 files produced the same counts and unknown-blocking value. This is a point-in-time observation, not evidence of a coherent locked snapshot or a Rust-owned observer. The live Python queue remains authoritative.

The same diagnostic subsequently read `config.json` through the same private directory custody and emitted only its safe queue settings: release-tag mode, local VM backend, v3.48.0 and v3.49.0. Synthetic tests refuse a symlinked, open-permission, or malformed config file. It does not reveal credential or arbitrary config fields.
