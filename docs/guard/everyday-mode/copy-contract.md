# Everyday Mode copy contract

## Required order

Every explanation uses: **action**, **target**, **consequence**, **why Guard intervened**, **safer next step**, then the **effect of the user choice**.

## Truth states

- **Attempted** means Guard observed the request before completion.
- **Prevented** means the authoritative outcome stopped execution.
- **Allowed, not confirmed** means Guard permitted execution but has no post-action proof.
- **Confirmed successful** and **confirmed failed** require post-action evidence.
- Capability language never claims execution.

## Confidence

- **Exact:** action, operation, and meaningful target came from typed or canonical facts.
- **Derived:** action family and consequence are known, but target detail is generalized.
- **Limited:** the full action cannot be explained reliably. Copy must say so and recommend stopping or opening technical details.

## Managed-state copy

Use “Required by your organization,” “Inherited from …,” “Chosen on this device,” and “Recommended default.” Presentation mode never describes a security setting as weaker or stronger.

## Cloud-state copy

Use “Saved on this device,” “Syncing,” “Cloud copy may be out of date,” “Could not sync,” and “Connected.” Cloud state never changes whether local protection is described as active.

## Prohibited claims

Never say an action ran, changed, deleted, sent, installed, or succeeded without the corresponding execution proof. Never turn unknown input into a confident friendly translation.
