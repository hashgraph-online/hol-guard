# Ordinary settings and CIGAR selection ownership

Replacing an existing selected CIGAR installation now requires the prepared SDK/data switch controls. An ordinary settings write that changes one nonempty runtime ID to another refuses before taking a lifecycle lease, verifying a bundle, starting an SDK or publishing profile bytes. The whole settings update is refused, including unrelated preferences in that request, so it cannot partially change the profile or interrupt the current actor.

This applies to all four old/new enabled combinations. It prevents a disabled replacement from bypassing migration as well as a running replacement from stopping the source before a target/data pair is ready. The native switch controls continue to use their dedicated serialized owner and exact settings CAS. [Disabled selection and rollback](CIGAR_OFF_STATE_SELECTION.md) remain available when the selected source installation is readable.

The refusal contains the native code `native_context_assistance_switch_required` and an existing `invalid` validation field: “Prepare and commit a CIGAR switch before selecting a different installation.” The existing Python settings client already prioritizes that validation field and raises an actionable `ValueError`. No Python runtime policy or settings-client implementation changed. The result therefore does not misreport a normal selection-workflow requirement as a configuration-file trust failure.

Same-ID preference writes, explicit opt-out, and the already verified same-ID enable path retain their behavior. Saving enable intent still does not attach a Service actor. Initial allocation, clearing the runtime ID and general reset retain their prior paths and still need complete selection/data-choice/recovery qualification. This narrow replacement guard does not claim those flows are complete or make the full P7 selection-routing requirement complete.

The actual SDK test uses a verified target plus a serving source on published final 0.14.1 and external CPython 3.14.7/3.14.10, with a test-only catalog/qualification on local macOS ARM64. A refused replacement preserves the exact actor, native generation, epoch, saved preferences and complete reviewed-note summary. A subsequent compile still returns the reviewed context. After explicit Stop, a disabled replacement also leaves profile bytes and actor absence unchanged. Enabling the same selected installation stores intent without SDK activation. The final test also checks the validation instruction in both refusals.

Two native regressions cover all enabled combinations with byte-identical profile preservation and no job-store provisioning, plus same-ID storage preferences and explicit opt-out. Native configuration tests pass 57 cases, with one child helper ignored; Service tests pass 19 with 17 explicitly gated SDK cases. The separately executed SDK case passes. Python framing tests pass 92 cases, including an isolated check that the existing settings client returns the intended validation message instead of a trust failure. These counts overlap and must not be added across suites or images.

Rust 1.88 production compilation, formatting, Python lint and native authority/I/O/privacy gates pass. Runtime Clippy retains the known 36 errors in 23 unchanged source files and reports no new error in the changed code. The earlier context and cold/live SDK acceptances retain their original source/image scopes; they are not relabeled as runs of this new image.
