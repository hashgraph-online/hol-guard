# Cold reviewed-data preparation and fresh admission

A disabled profile can now prepare reviewed saved data for a different exact SDK producer without reconstructing an app scope or enabling CIGAR. Deferred data stays sealed until a later explicit source grant and note-read permission prove the same source content. Existing native transaction primitives can commit that SDK/data pair while keeping enabled=false. The public bounded off-state selection job and CLI/HTTP action are still required; this checkpoint does not expose a complete off-state operator workflow.

## Closed-store proof

The native caller owns the profile lifecycle lease and supplies scope ownership rows from the profile's verified MAC index. Every current unexpired cache slot must be attributable; unknown, pending or damaged stores refuse before selection changes. Expired unmapped slots remain untouched and contribute no eligible data. Legacy ownership is not guessed from a hash, SDK version or workspace path recovered from disk.

Cold export inspects existing slots without sweeping them, creating a namespace or rewriting their manifests. A temporary verified source SDK opens each existing broker store, compares the complete native note vector with actual SDK provenance, and checks every basis revision/digest. Those metadata queries leave the native SDK source catalog empty. No old view, client, ticket, pairing, source permission or execution approval is reconstructed. Each domain closes before the exporter returns. SDK opening/closing may checkpoint its own database; only the native manifest and reviewed-data preservation are claimed byte-identical.

The maintenance configuration is private to that explicitly requested operation. It does not update the profile or configure a serving Service actor. Status, catalog reads and ordinary saved-data inspection do not call this exporter. The final SDK case uses actual native MAC attribution from two previously granted scopes, not caller-supplied ownership on an operator wire.

## Deferred generations

The existing protected generation store now distinguishes pending live imports from deferred reviewed data. A cold generation can be Ready for SDK/data selection with deferred scopes still unadmitted. That readiness is not a source grant or serving runtime. The private MAC binds each transfer's original SDK/interpreter identity, complete reviewed vector, scope hash, basis digests, creation time and expiry. Existing records without the new variants/optional provenance fields retain their old interpretation.

Further selection carries unadmitted transfers from the authenticated generation rather than opening project files or relabeling them as data produced by an intermediate SDK. Normal live preparation also carries deferred entries it inherits. A placeholder empty target cache does not replace the original deferred review. Partially acknowledged nonempty target state refuses for recovery. Inherited reviewed data requires persistence qualification even when no new transfer came from the current SDK.

Cold/deferred preparation identity includes complete semantic transfer data, including expiry and original provenance. Ordinary live preparation without deferred entries retains its previous identity format. A lowered retention limit is persisted into pending/deferred transfers before expiry. Raising the preference later cannot extend that cap, and retrying an older preparation refuses if its semantic input changed. Expiry removes staged text instead of resurrecting it through a later generation.

Imported entries retain original provenance separately from the selected producer. Scoped erasure does not mistake an ancestral audit key for a physical slot in the immediately preceding generation. Native attribution still must cover every actual cache. Erasure removes deferred text, imported slots and attributable legacy copies while preserving unrelated apps and their live SDK state.

## Fresh admission

Normal activation verifies the selected SDK/data pair but creates no app scope. A later grant first admits current protected source content. Without note-read permission, the app receives no deferred notes; the sealed transfer remains available for a later decision. An empty target can close and reopen without consuming the transfer.

With current note permission, the engine requires the selected generation's exact cache, the same app/workspace namespace, an exact verified target producer and matching fresh source basis. A different generation's slot refuses before any note mutation, even when its key and source documents match. Missing or changed source content refuses without overwriting the sealed original. The remaining source-change/data-choice experience still belongs to P6/P7/P8.

A reopened empty SDK target may import only while both native and SDK note versions are zero. If SDK commit succeeded before native acknowledgement, recovery compares the actual SDK version/digest and reconciles the native intent; it does not submit the mutation again. The test interruption hook remains test-only and is absent from native request schemas. Target backend restore state follows the actual SDK storage state after import.
