# Retained Python worker file custody in Rust

The new `read_python_worker_terminal_root_owned` reader opens only `/var/lib/hol-gauntlet/outputs/<16-hex-job>.json` and the matching `<job>/report/result.json`. It requires Linux Root, Root-owned non-writable ancestry, private 0700 output/job/report directories, regular 0600 single-link files, no symlink traversal, bounded bytes and stable descriptor/path metadata before and after reading. It passes the exact bytes to the existing `verify_python_worker_terminal` consistency check against caller-supplied source, job, deployment and config digests, then rereads both files to refuse a changed cross-file snapshot. The uninstalled `gauntlet-python-worker-shadow` binary exposes this diagnostic without accepting a path or command selector.

Four local library tests passed: the pinned synthetic receipt/report pair with a wrong-pin refusal, missing/mutated/unsafe report refusals, symlink/hardlink receipt refusals, and denial of unprivileged live access. The static ARM64 evidence test binary had SHA-256 `85476cda70532309804be57e6cf907cb8e505011ed1b1e5d67f4692e614bd69e` on both host and VM; all 24 unprivileged Linux unit tests passed, including the four new custody cases. On 2026-10-20, the final static ARM64 diagnostic had SHA-256 `8f41ac690f5910340227c2359f09b85c39e7705497c04510db3eaa2b0e38d7bc` on both the Mac host and idle 16-GiB VM. Unprivileged execution returned exit 2. An earlier draft was run as Root from `/tmp`; because that path was writable by an unprivileged user, its result is discarded. The final binary was copied to a Root-owned 0700 path, rehashed there, and run read-only as Root against retained job `4bd231e6a95d3c67`. It returned `receipt_consistent: true`, `producer_claimed_status: passed`, report digest `6cd2e92ac865b95bf1e3289058c2486647a5add86220446aab4a2e02b835d2a9`, and `execution_eligible: false`. Replacing the config digest argument with 64 zeroes returned exit 2 with a report/receipt mismatch. Both temporary copies were removed after the check.

The source/deployment/config arguments for that VM invocation were observed read-only from the retained receipt and deployment on the same machine. They are test inputs, not an independently reviewed controller generation or trusted publication anchor. This reader does not verify the Python worker executable, recompute six deterministic controls, authenticate installed Guard identity, or grant a benchmark verdict. No candidate process or model inference was started.
