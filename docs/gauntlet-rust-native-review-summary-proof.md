# Rust Native review completeness relation

`gauntlet-evidence` now recomputes Python's `review_summary` from reported Native Pre/Post and contained-route events. It counts required and completed Post reviews per call, distinguishes a native Pre refusal from backend admission, records incomplete attempts and all unreviewable fallbacks, and rejects a producer summary that differs from the recomputed result. The reader returns `execution_eligible: false` even when the summary is internally complete.

`ci/gauntlet-rs/proofs/generate_native_review_summary_vectors.py` extracts the actual `review_summary` AST from `builtin_hook_supervisor.py` SHA-256 `07625e4899849fa0eed54483756643e5c43d4989b2e61a8ace834315573a0caf` and `review_completed` plus its full reason vocabulary from `native_review_status.py` SHA-256 `1183eaa748d6855059b5e11a879570e47ea63b55ff7e4c4d3dc492474851165f`. It runs those functions against synthetic data without importing a candidate Guard package. The frozen fixture `native_review_summary_v1.json` has SHA-256 `f1cd3439548885d4016d5480f55b543e341e7de0f0168106b42d6f541df0e485`: 20 summary cases and 39 direct review-status cases, including every one of the 28 Python unreviewable reasons. Two targeted Rust tests passed in the pinned native ARM64 Rust 1.88 image, as did warnings-denied Clippy.

The inputs are supplied JSON. This proof does not establish that an SDK peer produced the events, that the Native hook actually ran, that the kernel observed the process, or that the product made the reported decision. It remains a subproof of deterministic control verification, not a live benchmark result.
