# Provider status and controller invocation parity

The Python v1 `verify_provider_status` function validates an externally pinned MLX adapter and an idle provider-quota snapshot before a controller treats provider counters as known usage. The Rust `verify_provider_status` function matches two accepted Python snapshots and sixteen refusals, including wrong adapter and binding pins, halted or pending usage, forged journal identity, boolean integer fields and inconsistent remaining budget. It returns the quota status as accounting data only; it does not grant model admission.

The Python `audit_invocations` function examines retained shard invocation directories and compares provider before/after counters with the controller ledger and aggregate token charge. The Rust `audit_controller_invocations` function accepts already-read immutable file bytes and outside config, manifest and provider pins. It checks exact retained file hashes, preflight binding, shard index, provider status and nonnegative before/after and ledger deltas. Its output always includes `qualification_eligible: false`. Fourteen Python-frozen cases cover absent/empty directories, preflight failure, a valid delta, aggregate mismatch, changed source pins or files, halted and decreasing provider counters, a wrong ledger delta and incomplete invocation files.

The read-only `read_controller_invocations_root_owned` entrypoint opens the state and retained invocation directories through no-symlink descriptors, requires Linux Root and private ownership/modes, refuses an active `ci-controller.lock`, bounds entries and total bytes, and rechecks file and directory metadata after reading. Synthetic owner-private unit tests feed its bytes to the pure reducer and reject an active lock, unsafe directory mode, hard-linked file, symlinked file and symlinked invocation directory. A SHA-256-matched static ARM64 unit-test binary (`596b7c08f750ac450ee606478cf1bc9b4f58efb4988230b8d8e887398df36b73` on host and guest) passed all 16 evidence tests unprivileged in the idle 16-GiB VM, including those custody cases. A subsequent 17-test binary also passed after the quota-prefix extension; see the [quota proof](gauntlet-rust-quota-proof.md). The Root-only entrypoint has not been invoked as Root on retained controller state, and a file snapshot alone cannot establish a completed benchmark.

Its [fixture](../ci/gauntlet-rs/crates/gauntlet-evidence/tests/fixtures/python_provider_status_v1.json) has SHA-256 `3b90187515df241a16bdc4fd49c4a831508907c84df325201d81d9ed6f0e8d06`. The [invocation fixture generator](../ci/gauntlet-rs/proofs/freeze_controller_invocations_v1.py) also pins `ci_runner.py` (`31f49df403c127986deff9a78eaaa252e4e52c51f6f3cb9018502fe4c5cf4ef5`) and `ci_runner_config.py` (`90e632c95ee511e048b0803c0a713b11f4ff282aad1c146e1f5ec9e4806e4bc6`). Its [fixture](../ci/gauntlet-rs/crates/gauntlet-evidence/tests/fixtures/python_controller_invocations_v1.json) has SHA-256 `0e6dc696f6673cf8453ab00ddad400d92773d453e6307f6381de46c5448e149c`. The fixture generator relaxes Python's Linux Root state-directory check only for its own disposable synthetic directory. It leaves production readers unchanged.

The remaining proof is a live Root-owned custody and interruption run on an outside-pinned controller generation, a binding to independently audited shard ledgers, and integration of the new historical quota-prefix verifier with a trusted outside final-hash anchor for retained provider snapshots. The Python invocation receipts are local-integrity records, not signed attestations. Until those boundaries and the live execution path are proven, these Rust functions remain diagnostic and cannot turn any result green.
