# One-use inert wheel staging proof

The Rust `gauntlet-candidate-wheel-stage-shadow` diagnostic reads only a previously captured Root-owned `candidate.zip` from a fixed build slot. Before writing, it holds both the Rust active lease and Python worker lock, verifies the source archive and captured artifact against outside SHA-256 pins, checks that the builder container, cgroup and AppArmor profile are absent, and validates every nested wheel entry, distribution field, runtime manifest and actual native bytes. It then creates an exclusive `inert-wheel` directory inside that build slot. All wheel files are streamed into descriptor-relative, Root-owned paths, mode 0444, fsynced and independently read back. The staged directory stays mode 0700. A failure leaves a one-use partial directory for inspection; no candidate file is imported or executed, and no installed prefix or deployment is created.

The first live use on v3.49.0 job `da85d9f817d98679` was performed with ARM binary SHA-256 `dbc6494a7ad773bf467941b48124ae18fdd866eaf9c0501e907040a69f5a45d1`. An unprivileged call and a wrong captured-archive digest refused before writing. The exact call streamed and read back all 1,708 wheel files, then returned `ReadbackMismatch` at the final aggregate inventory check. The check incorrectly compared the inventory's file **plus directory** count to the wheel's file-only count. The retained partial tree was not retried or promoted. The pinned Python inventory observed 1,708 files, 1,746 total entries, 52,600,062 file bytes and tree digest `e79826ed27a5c618a919b07081551d61e4d720da96e6802e64b7cbf5d23dbd19` in that directory; this observation does not convert the failed transaction into a success.

The correction counts unique wheel path prefixes as directories and requires `inventory.entries == wheel.entries + directories`. The synthetic ARM Root test now checks that identity, exact file readback, malformed-wheel refusal before creation and replay refusal. A SHA-matched test binary `b879397290aa4e41ae3a6774805d68998da7e2508b4fd6cb5813fb10a88049e4` passed that test on the live VM. Warnings-denied ARM64 Clippy passed.

The corrected ARM diagnostic, SHA-256 `7619cfa15bdb871c6fa95430fa465b57325f94de4fd2ae559a2b8d3f1f792983`, was installed Root:Root mode 0500 with one link. It used the separate fresh v3.48.0 release build job `aaabefe820493283`: source commit `3864097f2e4fe623e403c1a948d9882f34c78690`, source archive SHA-256 `5d3eeff80bedd07042a28ffdf5d0192500669b238384ca71f7a3f8631f9382be`, retained candidate archive SHA-256 `a427dad674c9cd0b37ee14b1d72483de6838b1e8fbfe95b224ecd5abd0da3944`, version `3.48.0`. The Root command returned `readback_verified:true`, 1,706 wheel files, 1,744 total tree entries and 52,181,110 bytes. Its staged tree digest was `cbafa46e0555764406450a1c5940a69c781352f4dfcfb932259396a19c8a387c`. The pinned Python `runtime_bundle.inventory` independently read the same directory and returned the same file count, total entry count, byte count and digest. A replay refused with `one-use inert wheel stage already exists`; a subsequent independent Python inventory returned the unchanged digest.

This establishes inert materialization and readback for one captured release wheel. The staged tree is only wheel data, not a dependency-complete installed Guard prefix. Dependency validation, baseline-prefix cloning, fresh signed conformance, immutable deployment, installed deterministic controls and actual inference remain open. Every diagnostic result reports `artifact_admitted:false` and `execution_eligible:false`.
