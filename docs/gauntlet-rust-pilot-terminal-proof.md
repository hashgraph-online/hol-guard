# Python pilot terminal parity proof

Code pin `501b93aa` adds `gauntlet_evidence::reduce_pilot_terminal`, a data-only Rust reducer for the initial terminal branch of Python `run_pilot`. `ci/gauntlet-rs/proofs/generate_pilot_terminal_vectors.py` extracts and executes that exact Python AST branch from `ci/gauntlet/benchmark/pilot.py`, source SHA-256 `f22d91cd79fa4504d717dafb7f953c8a671a177ceee78425a4e8ee96e6fc71b7`, branch AST SHA-256 `4980ccf63b8c41d4b8894549f3da225b4450e2a76cfde4a7c00641fa639347f8`. The fixture covers 23 cases: zero/nonzero/missing process exit, missing and error events, isolated cleanup, live services, both retryable startup errors, inference-start and controller-error retry exclusions, and last terminal selection. The Rust test checks the Python source pin against `parity-manifest.v1.json` and the exact AST digest.

The new parity test passed both locally on macOS and in an offline native Linux ARM64 `rust:1.88.0-slim-bookworm` container. The full macOS `gauntlet-evidence` crate passed; local warnings-denied Clippy and workspace formatting passed. The ARM image did not have the Clippy component, so ARM Clippy was not run. An isolated ARM64 CI step now runs this parity test on future PR heads.

The Rust reducer refuses malformed field types, negative or overflowing service counts, malformed event entries and more than 50,000 events. Its input is supplied JSON. It does not authenticate producer events or process identity, measure model/provider usage, run a cell, decide Guard effectiveness, or replace the later Python budget and qualification logic. The OMP bridge and model-backed workflow parent exits remain open.
