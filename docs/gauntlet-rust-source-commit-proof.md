# Inert source archive Git-graph proof

The Rust host can now check that a retained, SHA-256-pinned Python `source.tar.gz` contains the exact release or local-candidate ref and a reachable Git object graph for the caller's 40-hex commit. This is a read-only diagnostic for migration parity. It does not fetch a source, unpack a product worktree, start Podman, admit a job or authenticate who supplied the outside pins.

`verify_retained_source_archive_commit` first uses the existing owner-only, no-symlink archive reader. It checks the archive digest, compressed and expanded size limits, unique ordinary tar members, and stable file identity. It then creates a fresh private temporary bare Git directory with a fixed config. Only validated loose objects, SHA-1 pack/index/reverse-index files and a bounded shallow boundary are copied into it. The archived config, hooks, refs, object alternates and worktree files are never installed there. The selected archived ref must be a single 40-hex object ID under `refs/tags/v3.48.0`, `refs/tags/v3.49.0`, or `refs/heads/local-<source-sha>`. A fixed `/usr/bin/git`, with an empty inherited environment and bounded output/deadline, peels the object to the outside commit and runs strict reachable-object `fsck`. The returned proof always has `execution_eligible: false`.

Six tests passed natively on macOS and in the Linux ARM64 source container. Real temporary Git repositories exercised a direct tag ref, an annotated tag, and a depth-one shallow fetch. A wrong commit and missing ref refused; an archived `objects/info/alternates` file refused before Git ran. The sixth test bound a successful archive proof to the same fixed release lookup plan: a matching ref/commit passed, a different release ref refused before lookup, and a mocked moved tag refused. The full macOS `gauntlet-host-state` suite, warnings-denied native host Clippy, and warnings-denied ARM64 workspace Clippy passed. The uninstalled `gauntlet-host-shadow-source-commit` command exposes the archive diagnostic for an explicitly supplied state root, job, archive hash, source commit and ref.

On code head `32879b91`, the same uninstalled command checked two **retained historical** host archives without changing the Python observer or VM. Release job `7b3dd7131df5fedd` had outside archive SHA-256 `5d3eeff80bedd07042a28ffdf5d0192500669b238384ca71f7a3f8631f9382be`; its archived `refs/tags/v3.48.0` resolved to exact commit `3864097f2e4fe623e403c1a948d9882f34c78690` and strict Git graph verification passed. Local-candidate job `e2f042a7344bbbb0` had archive SHA-256 `bedd98ab7da8ca728484799e1ef6b13c854f7fcbb31a17ebdcc469c4c772af43`; its `refs/heads/local-76c31929833b5571d25a56d9783e24a0997d5422` resolved to exact commit `76c31929833b5571d25a56d9783e24a0997d5422` and verification passed. Both outputs reported `execution_eligible: false`. The archive and commit pins came from retained host/job observations, not an independently reviewed source authority.

The separate uninstalled `gauntlet-host-shadow-source-tag-recheck` command then read the existing release-only local-VM operations config, reverified retained job `7b3dd7131df5fedd` and queried its exact `v3.48.0` tag again through the bounded Git plan. It returned `git_graph_verified: true`, `tag_unchanged: true` and `execution_eligible: false` for commit `3864097f2e4fe623e403c1a948d9882f34c78690`. The mocked integration test separately refused a moved tag and a different release ref. This live query is a point-in-time read-only observation, not a recheck inside a one-use Rust admission transaction.

This proof does not establish independently authenticated GitHub origin, a live moved-tag recheck inside an admission transaction, independent review of the outside commit/archive pins, source transfer to the VM, image/profile custody, Podman build confinement, or a product result. The scratch copy needs bounded temporary disk space and the fixed Git executable needs separate custody before any admission use. The Python observer and release queue remain authoritative and passive.
