# Fixed Rust contract for the existing model-provider launcher

`fixed_live_provider_start_plan` builds the macOS host's exact Python `uv` command for one validated job, profile and candidate Git SHA, with a caller-supplied absolute reviewed repository path and the Python 900-second timeout. The fixture generator evaluates the command list from `live_local.run` and the startup return expression from `live_provider.start` without spawning either. Three Python-produced profile cases match the Rust plan and bounded final-JSON-line parser. The integration source map pins `live_local.py` SHA-256 `71c243e73702aef416db1a55108635a755f0a4ba4158c89723ca41d76e56af60` and `live_provider.py` SHA-256 `650b1964a1aba988ccd239f13a933ea0697d9b169656f72a86999d5b015a25db`; the test also pins the selected command/return AST hashes. The provider-source change adds a durable candidate/job/profile binding to later records; the selected startup return expression is unchanged.

The parser rejects malformed or extra JSON fields, duplicate keys, an unexpected provider root or manifest path, changed model identity, zero/invalid PID, changed preflight token count or cap, and invalid digest syntax. Both tests passed on macOS and Linux ARM64 Rust 1.88; local warnings-denied Clippy and Python generator Ruff passed. The ARM64 PR workflow now runs this integration test.

The parsed result is explicitly `producer_claim_only:true` and `execution_eligible:false`. It does not verify manifest file bytes, attest the PID, own the child process, hold the quota lock, or authorize the source against a renewed allowance. The Rust host supervisor must establish those relations before it can replace the Python launcher.
