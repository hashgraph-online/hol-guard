# One-use host candidate build intent journal

Code pin: `bb686832`. `gauntlet-host-state` now has an isolated Mac-owned intent journal for a future builder launch. A caller must create its private 0700 directory outside the live Python observer state. For one 16-hex job ID, the journal binds an exact source commit/archive, package version, controller tree, builder image, AppArmor policy, four fixed helper digests and the runner/result-reader binary digests. The host generates a 256-bit nonce with the OS CSPRNG; the canonical record is written only once as a 0600 no-symlink file, fsynced with its directory, reopened, and rehashed. A partial file consumes the job ID. Reads reject wrong owner/mode/link count, malformed or noncanonical JSON, symlinks, and a replaced private directory. `Cargo.lock` adds only the already-locked `ring 0.17.14` dependency to the host crate.

Three targeted macOS tests passed: durable readback after reopening and replay refusal; wrong image ID, partial file and symlink refusal; and swapped or loose directory refusal. The same three tests passed in the native ARM64 build container. Warnings-denied macOS and ARM64 host Clippy and workspace Rustfmt passed. The fixture values are the previously observed historical local 3.49.0 source/image/helper identifiers; the tests did not run a build or contact the VM.

This is a host-owned prelaunch **intent** primitive, not evidence of prelaunch ordering for a real job. No host process has yet recorded a pin before invoking the VM, no VM request or result contains this nonce/digest, and no independently reviewed binary or controller generation has been approved. The journal therefore reports `execution_eligible:false` and cannot authenticate or admit the earlier 3.49.0 artifact. The next boundary is a single host-owned request/ack transaction that persists this record before any candidate Podman spawn and reconciles the resulting terminal bytes against it after restart.
