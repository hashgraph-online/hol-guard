# Local review and release gates

This package is an exploratory workflow benchmark implementation. The approved
scope permits local implementation and owned-VM validation. It does not permit
production CI/CD edits, remote runs, publishing, releases or qualification claims.
The original planning package remains unchanged.

## Authored coverage

Eight public challenges and their expected answers cover developer temperature
boundaries plus sales quarter close, BD evidence conflicts, marketing consent
revocation, support SLA boundaries, finance credit notes, HR time zones and
operations role drift. Their fixtures disclose implementation-team authorship,
nonblind custody and dependent authorship. No independent holdout claim follows
from this coverage.

[AUTHORED_CASES.md](AUTHORED_CASES.md) publishes the eight local source cases and
their disclosed answers, with direct links to each JSON fixture. Public workflow
and snapshot loaders are in [authored_challenges.py](authored_challenges.py);
answer loading and instance-specific scoring stay in the controller/worker path.
The inventory is reproducible with `python -m ci.gauntlet workflows preview --authored-challenges`.
Publication here means public repository inputs, not external publication or a
completed live campaign. Retained authored finance diagnostics are linked from
[PROGRESS.md](../../../PROGRESS.md#published-authored-source-and-retained-diagnostics).

The complete inventory is 800 base cells, 140 approval cells and 160 authored
challenge cells. A preview is a schedule, not proof those 1,100 cells ran.

## Evidence required before release qualification

1. Validate the newly integrated unprotected developer campaign executor and
   two-session approval executor with current-source live episodes in the VM.
   Developer routing has host scheduling/evidence audit proof; the protected
   builtin/MCP runtime still needs authenticated SDK conformance. Mechanical
   authored worker controls prove actual candidate-written test execution and
   rejection of a nonfinite-bug CLI; fresh authored model episodes remain required.
   Bind each cell to its exact variant, snapshot, authorization, public
   task, policy, worker proof and outcome. Unsupported mediation stays explicit.
   Never substitute direct tool replay or copied successful diagnostic rows.
   Validate complete live workflows through the newly implemented UID10004 product
   lane. Its official MCP conformance passed clean delivery, injected-response
   interception and private-path denial; that is not complete workflow evidence.
   Candidate probes and imports must execute inside that boundary. The older
   root-owned proxy diagnostic is not an untrusted-product boundary.
   Approval validation must use v2 scope freezing and a progressing controller
   clock, with externally authenticated durable application timestamps. Expiry
   must be rechecked under the transaction lock and after staging, with atomic
   rollback. The pilot declares its exact lifetime; it cannot forecast application
   time or treat a held logical clock as real expiry evidence. A live elapsed-expiry
   claim requires an externally signed actual refusal/expiry witness. The separate
   elapsed-clock control below provides mechanical MCP conformance only; live model
   phase reports and complete workflow evidence must establish their own outcomes.
2. Exercise all declared developer attack channels and the authored developer
   boundary vectors in authenticated workers. A base CLI diagnostic cannot stand
   in for an authored challenge or attack variant.
3. Freeze a supported tuple: source commits, native wheel/runtime, policy, SDK,
   model/provider identity, service images, observer, schemas, oracle and verifier.
   Public artifact identities must match actual execution; current local model
   ID/endpoint evidence does not independently identify the model's weight bytes.
4. Review the new schema and oracle verifier through the existing Gauntlet trust
   policy. Prepare exact source/data/test identities for independent review. Do
   not make candidate code eligible merely by copying its revision into a local
   environment variable or changing existing trust policy.
   The existing [trust policy](../trust.py) has a pinned initial-install exception
   for repository `hashgraph-online/hol-guard`, PR 3463 and an exact bootstrap SHA,
   only when Gauntlet is absent from the independently resolved base. This work
   starts from a Gauntlet-enabled base, so that exception cannot self-promote the
   new workflow oracles. Eligibility requires independent review and deployment
   through the existing trusted-base/default-branch path. That deployment is
   outside this local-only authorization; local control evidence stays useful
   without claiming verifier eligibility. No permission or policy change is implied.
5. Run the full preregistered 1,100-cell actual-inference campaign within the
   approved global budget. Retain invalid runs, refusals, unsafe effects, startup
   retries and budget failures. Charge actual provider total tokens, including
   cache/input and any final-response threshold crossing. A soft episode threshold
   is not a guaranteed provider-side maximum.
6. Export the complete public-safe signed data bundle with separately supplied
   controller/effect anchors. Independently verify every scheduled cell and file;
   self-consistent signatures alone do not establish signer eligibility.
7. In a second isolated environment, verify the entire exported bundle and run
   the separate 32-cell public live reproduction slice. Keep its evidence and
   denominators separate from the primary campaign.
8. Complete the appropriate existing local checks, audit the acceptance matrix
   AC01–AC10 and document owned-resource cleanup. Production CI results remain
   outside this local authorization and cannot be reported as green.

## Interpreting current measurements

The legacy replay module now has a complete local rerun with **4,206 passes and
124 expected failures**, with no unexpected failures or skips. The original broad
run's 844 failures remain retained. They came from missing overlay-capable
Bubblewrap and the VM's group writable synthetic loader directories under umask
002. Provisioning the existing CI prerequisite and a private process umask made
843 pass; one matched its unchanged known-gap expectation. All 4,330 replay names
and expectations are unchanged. The 124 known gaps remain release considerations;
this rerun does not establish production CI status or workflow qualification.

Version two approval clock controls have local regression proof over exact grant
boundaries, lock waits, staged-effect rollback and signed application-time binding.
Legacy logical-clock diagnostic evidence is preserved. The new controls require
a fresh live tuple before campaign evidence can use them; old reports cannot be
upgraded to actual elapsed expiry or secure completion.

The [actual elapsed-clock control](approval_elapsed_control.py) subsequently ran
inside the owned Linux VM's neutral root controller. Its separately anchored
signature covers a valid before-expiry effect and actual refusal/replay after a
two-second grant expired. The expired world stayed unchanged, with no consumed
claim, and both official MCP sessions closed. Its [public evidence](../../../../local-evidence-20261013/approval-elapsed-control-20261013/manifest.json)
pins the original source snapshot and exact report bytes. This closes that bounded
mechanical conformance check; it does not validate a model preparation, full approval
workflow, installed HOL Guard approval surface or campaign. Old logical-clock
reports and frozen model evidence retain their original limitations.

Real model diagnostics have produced both completed developer tasks and failures.
An external denial completed two genuine agent sessions, but its business
preparation still failed independent checks. Model grant attempts were refused
before granting unintended scopes. These failures are measurements, not startup
infrastructure errors and not evidence of secure task completion.

The actual native MCP frontdoor delivered the ordinary task-delegation attack in
one control and withheld an explicit safeguard-override control in another.
The new audit candidate records a content-free native block with its actual
upstream response digest. Its matching signed transport/effect/audit evidence
establishes that particular interception; it does not establish general task-scope
protection, factual correctness or complete benchmark performance.

Model refusal, provider ACLs, approval-controller decisions and VM containment do
not count as product interception. Guard's external approval surface is currently
unsupported. Scores must distinguish task completion, security, exposure,
intervention, attribution and missing proof.

Keep product repairs separate: reproduce, retain the failure, apply the repair,
run conformance and regression checks, then freeze a new candidate. Do not edit
old evidence or combine the best rows from different source versions.
