# Signed provider-budget parity proof

Code pin `27bbdfdf` adds `gauntlet_evidence::verify_signed_model_budget`; `5dcac13d` adds the two optional MCP profile declarations. The reader verifies an 8-MiB-bounded canonical Ed25519 envelope against a caller-supplied public key, compares the fixed Python observer source hashes with outside pins, then recomputes requests, responses, knownness, tokens, threshold overrun and cleanup from the ordered provider rows. It never accepts the SDK's `modelTokens` or `episode_end` as provider authority.

The fixture generator calls pinned Python `business_model_budget.verify_model_budget` with deterministic test signatures. The source SHA-256 is `1b72f0af2653b6c2e9da345a9009d056402f3a278dc9e07536a936c916f7fd4a`; its endpoint helper is `82cf4f951340e0c9cc65315b31f042aef235d378a661d4b5246f36db29d3f302`. The cases cover complete, zero-request, startup-incomplete, overrun, pending, partial and legacy observations; discovery and sequential requests; known and unknown cost; valid protocol and agent-surface profiles and their combinations; signature, source, route, sequence, aggregate, threshold, sampling and cleanup mutations. A separate Rust test refuses a wrong outside key, wrong outside source hash and excess bytes.

Code pin `e0521b5a` adds `read_signed_model_budget`: it opens only `model-budget.json` through no-symlink ancestry, requires a regular single-link file, rechecks descriptor identity/size, bounds it to 8 MiB and compares the exact bytes with an outside SHA-256 before verifying the signature and accounting. Three integration tests passed on macOS and Linux ARM64, including changed digest, hardlink, symlinked parent/file and oversize refusals; local warnings-denied Clippy passed. The reader does not establish Root ownership or the provenance of its caller-supplied hash and key.

This reader supports the fixed v1 record and validates the exact optional MCP protocol and agent-surface declarations. Those declarations do not prove protocol delivery, selected tool inventory, model ingestion or Guard effects. The reader does not retain a live provider transcript, prove the public key's deployment provenance, establish a candidate's model use, settle the host quota journal, or qualify a Guard result. The provider and model-backed workflow exits remain open.
