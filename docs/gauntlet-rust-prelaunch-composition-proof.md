# Read-only Rust prelaunch composition on retained ARM VM

On 2026-10-20, the uninstalled Linux ARM64 `gauntlet-prelaunch-shadow` diagnostic exercised one bounded synthetic `run` request against the idle 16-GiB VM `hol-beta-bootstrap-20261016-004`. It composed the fixed Root-owned deployment reader, complete controller-tree verifier, interpreter-byte reader, v7 config loader, all declared inert asset readers, and the fixed deterministic launch plan. The local and guest binary SHA-256 both matched `5fd51812c4c912040f898ecbd0f01234495f2622308e0c6bd6e2e747de2035e5a`. The diagnostic only read existing files. It did not reserve the synthetic job, create a cgroup, spawn Python, or write a report.

The retained source pin was `b4efd8171b06d0e13cbe12a077c376ecdc891fd1`; the deployment manifest raw SHA-256 was `e65ab14fb8cb3d4ecb5f5eec3ff96170b2d6efd24c51e5a14d428e4427011e36`. A separate uninstalled `gauntlet-controller-observe` binary, SHA-256 `810ae786b0ffae95e0cd5d7a66742b60e65c26cfc25e11cf778df4ef6048b6de` on both host and guest, read the deployment and reported an **observed** controller-tree digest `7e966cb104439943942c7fc99937c266130f884bd019f38b38cf0f0294debb9f` over 506 entries and 5,199,948 bytes. The interpreter digest `c86f21d0da9290ece2d7d49a3f7ed52aed59cb029abdf0ea25c79634f6cbe960` was likewise observed on the retained VM. Neither observation supplies independent reviewed pin provenance.

With these four arguments and a 1-KiB-bounded request for synthetic job `aaaaaaaaaaaaaaaa`, the Root diagnostic returned the expected source/deployment/controller/interpreter digests, config digest `97dcf0337f2f98539212390d969a30c2290d3123ce99d8a3aeba7725d54f7568`, 506 controller entries, 13 verified asset roles, and the fixed Python `ci check --profile deterministic` argv, cwd, environment, state root and output paths. Its JSON explicitly set `outside_pin_provenance_verified`, `interpreter_execution_bound`, and `execution_eligible` to `false`. An unprivileged invocation exited 2 with `Linux Root required for prelaunch custody`; a wrong controller-tree digest exited 2 with `controller tree differs from outside digest`; a wrong interpreter digest exited 2 with `deployment declaration differs from its outside pins`.

This proves the composed readers can inspect the same retained v7 deployment without a hidden path or format mismatch. It does **not** prove that the controller is a reviewed generation: the [source audit](gauntlet-rust-controller-source-audit.md) found the installed tree differs from both tracked Git maps, and the digest above was measured from that same tree. A real worker still needs an independently reviewed install pin, authenticated outside pin delivery, descriptor-bound interpreter/controller execution, exclusive reservation, cgroup deadline and descendant cleanup, independently scored results, and fresh Rust-controller conformance before any execution claim or cutover.

The Rust workspace test suite and Clippy passed on macOS. The Linux ARM64 `gauntlet-worker-state` test binary had SHA-256 `16e14a6e6915091ceff527085e21ec9b0b28d2f34e551931ee4f6a2e21372326` on both host and VM; all 15 library tests passed on the VM. Three existing process/cgroup tests failed when the same binary ran inside Docker because its cgroup namespace did not expose the host layout those tests require. The VM result is the relevant environment check for that test family; the Docker failure remains visible rather than being counted as a pass.

The next Rust revision retains the verified system-Python executable descriptor in `HeldInterpreter` through asset verification and fixed-plan construction. `PreparedLaunch` can hand that descriptor to a future dispatcher; `checked_fd` rechecks the same open inode before exposing it. A SHA-matched ARM64 worker test binary (`43b36dd829082f5bded2ec5bfd068b335e800fea703799ce735b4cf744016a57`) passed all 16 library tests on the VM, including a new Root-owned executable-descriptor test and an altered-metadata refusal. The rebuilt prelaunch diagnostic (`a6f977d4f28cecc0bbce206c104af2217c45025efed928347a2b9c82da94b405` on both host and VM) returned the same positive 13-role proof and refused a wrong interpreter hash with exit 2. These temporary binaries were removed after proof. The descriptor is held during inspection only; no `execveat`, cgroup placement, process identity or controller import has been bound to it, and `interpreter_execution_bound` remains `false`.

A later [inert interpreter-execution probe](gauntlet-rust-interpreter-exec-proof.md) did bind that held executable descriptor to `execveat` and preserved the venv prefix. The prelaunch diagnostic above remains read-only, and its `interpreter_execution_bound: false` value still correctly describes the benchmark launch plan; Rust has not executed controller code.
