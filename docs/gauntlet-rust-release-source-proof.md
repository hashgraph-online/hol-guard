# Rust fixed release-tag source proof

`gauntlet-host-state::TagLookupPlan` reproduces the pinned Python `local_vm.resolve_release` Git argument vector for an allowlisted stable tag. It fixes the disabled hook path, Git object fsck, cleared credential helper chain, existing `gh auth git-credential` broker, exact `refs/tags/TAG` and optional peeled ref, GitHub URL, and `GIT_TERMINAL_PROMPT=0` environment delta. Its separate read-only executor runs that fixed Git vector directly with no stdin, bounded stdout/stderr and a 60-second child deadline. It does not inspect credentials, fetch an archive, or admit a job.

The fixture generator verifies `ci/gauntlet/control_plane/local_vm.py` SHA-256 `b7f4274c4656dba13ec7b3dcc71ad96a71b0cc4dd8fccca2218041fc3db3aa20` and calls Python's actual `resolve_release` with `subprocess.check_output` replaced by an in-process result. Fourteen cases freeze the exact argv, direct and annotated tag results, quoted helper path, and refusals for unlisted tags, missing refs, duplicates, unexpected refs, malformed columns and invalid SHAs. Rust matches the accepted values and refusal classes. Its parser additionally bounds output to 64 KiB and rejects invalid UTF-8. Local tests exercise a fixed fake Git executable's success/failure and kill a nonterminating child at a short test deadline. Isolated native ARM64 CI runs the same cases.

On 2026-10-20, the uninstalled `gauntlet-host-shadow-tags` binary read the retained Mac host's private operations config through an owner-only, no-symlink descriptor and performed the two allowed read-only Git lookups. It resolved `v3.48.0` to `3864097f2e4fe623e403c1a948d9882f34c78690` and `v3.49.0` to `e3f9e7eb4e0cc7b1987780a62697e8bb221ae050`; a separate call to the pinned Python resolver returned the same pair. The Rust diagnostic reported `admission_eligible: false` and made no queue or VM change.

The private config read and bounded Git lookup are real, but the Git executable and credential-broker bytes are not independently attested, a second lookup at admission is not wired, and no fetched commit or archive bytes are checked by Rust. Tag movement, remote failure, and a changed source after this observation must still block any future admission. The Python release observer remains authoritative.
