# Bounded Rust stop of one job-owned product-cell slice

The Linux Rust worker-state crate now has `stop_rust_job_slice(job_id)`. It accepts only the parsed 16-lowercase-hex job ID and derives the exact `holgauntletrust<job-id>.slice` name. Root checks the cgroup parent and the present slice through no-symlink descriptors and stable ownership/inode observations before running the fixed `/usr/bin/systemctl --system stop <slice>` command with a cleared environment. The command has a 10-second bound; a successful stop must be followed by a separately observed disappearance of the slice cgroup within three seconds. Unreadable, unsafe, changed, surviving or uncertain observations fail closed. An already absent slice produces a no-op observation. The uninstalled ARM probe hard-codes job ID `fedcba9876543210`, so it cannot select an arbitrary unit.

On the idle 16-GiB `hol-beta-bootstrap-20261016-004` VM, the stripped probe SHA-256 matched on host and guest: `15a356efc55601651e76d615ff33ea412d8b4b00412bb798b80471d4e498f634` (594,632 bytes). An unprivileged run refused Root access; a Root run with no slice returned `stop_invoked:false`, `slice_absent:true`. Root then started only `/usr/bin/sleep 120` as an inert transient service under the exact job slice. Independent `systemctl show` reported `ActiveState=active` and `ControlGroup=/holgauntletrustfedcba9876543210.slice/hol-rust-job-slice-stop-probe-20261020.service`, while `stat` found the Root-owned 0755 slice directory. The same Rust probe returned `stop_invoked:true`, `slice_absent:true`; independent `systemctl show` then reported the service inactive and dead with no control group, and `stat` reported the slice cgroup missing.

Three slice-guard unit tests passed in the ARM container. A SHA-matched stripped ARM64 worker-state test binary (`79022d1a172664532d12eb28a2c1630b2db3b398f3ac8e977a8df19873b89b54`) then passed all 24 Linux unit tests unprivileged on the VM. The first VM run exposed a synthetic fixture's guest umask making its directory group-writable; the fixture now explicitly sets private mode and the full rerun passed. The probe and both temporary test binaries were removed from the guest; root filesystem free space was 8,660,406,272 bytes, above the 8-GiB floor. No controller, candidate product, benchmark or model ran.

This stop operation is a **necessary cleanup primitive**, not a complete worker terminal proof. The caller must still hold the exclusive job lease, stop and reap the actual controller before it can create another product-cell unit, bind that controller and every systemd unit to the job, independently account for any surviving process or unit, and leave the job unknown if any observation is uncertain. The current Python worker and passive PR gate remain authoritative.
