# Rust local conformance package shadow proof

This is a read-only diagnostic over one **historical Python-produced** local conformance package. It does not run a control, authenticate physical effects, authorize candidate execution, or qualify a benchmark result. The initial implementation source is commit `b4fafe37`; that static Linux ARM64 binary SHA-256 is `e7800bd87b4b73372b0d6655ddccf32674fd5195a6a83953183f4649db204d81`. The binary was installed Root:Root mode `0500`, one link, at `/opt/hol-gauntlet/gauntlet-local-conformance-shadow-e7800bd8` in the idle `hol-beta-bootstrap-20261016-004` VM. The later key-pin extension and its final binary are recorded below.

Outside inputs to the Rust read were the v7 config canonical SHA-256 `e28d37d51438dfbd771e537579003693cb0aaace51a14f6f40c9e14feea410c1`, the historical Root-owned controller tree digest `bf2d2c7fd5d672209904cc29f3519a7500c1085df5fcf20cfbc9bff1b5057076`, and the config-pinned package SHA-256 `93d3bfd73301e9b095b41b856a7b208455c999ee2b83e0ecacaab0f19368d78d`. The config belongs to retained candidate source `76c31929833b5571d25a56d9783e24a0997d5422`, package version `3.49.0`; its package and config files are under `/opt/hol-gauntlet/candidates/76c31929833b5571d25a56d9783e24a0997d5422/`. The old controller generation is `/opt/hol-gauntlet/controller-8285b68c3198aec1`. These pins were observed on the same VM, not independently approved for production.

The Rust reader rechecks the complete controller tree, loads the outside-pinned config, hashes every declared file asset including conformance, then compares all 50 exact named execution-source files to the package. It independently inventories the SDK tree and Bun bytes, size and mode from no-symlink descriptors, comparing both with the config and package twice. It matches the observed Linux platform and config-derived runtime tuple, written review fields and review-document digest, five canonical record digests, five signed controller openings and reported tails, and distinct session IDs. It recomputes five Native review summaries from signed event rows, four completed contained-route/output relations, four signed public-prompt relations, four fixed contained-CLI result relations, and the cancel role's separate partial-capture relation with its expected missing Post. The general completed-route reducer correctly refused cancel's consumed-but-unfinished route on the first integration attempt; applying Python's cancel-specific branch resolved that mismatch. It reads the controller tree and file assets again before returning. No Python candidate code is imported by Rust.

The SHA-matched binary returned five roles (`boundary`, `cancel`, `input-binding`, `success`, `timeout`), 50 source hashes, five distinct sessions, five recomputed review summaries, four matched routes, four exact output bindings, four public prompts, four contained-CLI results, and one checked partial cancel relation. It reported `public_inputs_verified:true`, `independent_kernel_sdk_effects_verified:false`, `qualification_eligible:false`, and `execution_eligible:false`. The historical Python `verify_local_conformance` on its matching old controller returned the same five roles and package digest with `public_inputs_verified:true`, `trust_status:local-integrity-only` and `qualification_eligible:false`; both observed 42,321 SDK entries, 1,053,309,967 bytes and Bun mode `0555`. Python was invoked with `-I -B` to avoid creating bytecode in the pinned controller.

Three read-only VM refusals were observed: a wrong config SHA refused before package opening; a wrong historical controller-tree SHA refused the complete tree; using the newer, otherwise matching controller generation `18d31910a8cefbd6` refused because execution-source bytes differ. Local tests also refuse a candidate-chosen runtime tuple, changed source hash, changed review document, duplicate JSON keys, wrong raw package SHA and an oversized package. The evidence crate test suite passed, and native plus Linux ARM64 warnings-denied Clippy and Rustfmt checks passed.

This proves the Rust diagnostic can consume a retained local package under exact config/controller pins and re-inventory its declared public inputs. The current Rust full-asset verifier refused this older deployment's private-cell bootstrap because its embedded controller source map belongs to the newer generation; the shadow reader therefore does not claim complete private-cell/prefix inventory for that historical config. The existing `verify_control_reported_tail` still checks producer-reported fields, not independently observed SDK, Native, kernel, cleanup or effect evidence. The current source-matched patched candidate has **not** run fresh conformance through Rust, and the older package cannot be reused as its admission. Fresh signed controls, independent effect scoring and an independently reviewed controller/install source remain open checklist exits.

## Caller-supplied control key comparison

Code commit `143fde87` adds a stricter optional read mode. The CLI takes exactly five distinct lowercase Ed25519 public keys in `boundary`, `cancel`, `input-binding`, `success`, `timeout` order after the controller-tree digest. Rust requires the complete key map before opening any control and compares each package key and signed record against its corresponding caller-supplied key. The existing five-argument diagnostic remains available and now explicitly reports `outside_control_keys_matched:false`; the stricter mode reports `true` only after all five comparisons succeed. Neither mode grants execution or qualification eligibility.

The SHA-matched static ARM64 binary `cafb7f7f9a588ccb485da2034106b7d929e70196f02be636415d6e53d0e9e669` was installed Root:Root mode `0500` at `/opt/hol-gauntlet/gauntlet-local-conformance-shadow-cafb7f7f`. It accepted the retained five-role package with a complete caller-supplied key map and returned the prior 50-source, five-session, four-route, four-output and four-CLI counts with `outside_control_keys_matched:true` and `execution_eligible:false`. A wrong boundary key refused with `control key differs from outside pin`; a no-key invocation returned the same read-only counts with `outside_control_keys_matched:false`. Unit cases reject a missing role, duplicated key and wrong key. The full evidence-crate suite passed, then the post-change 30 library tests and native/Linux ARM64 warnings-denied Clippy passed.

For this historical diagnostic, the five public keys were read from the package on the same VM and supplied back as arguments. That verifies Rust's comparison path, **not** an independently authenticated host key pin. A qualifying fresh Rust run still needs a host-retained, one-use key map created before each control starts, bound to the exact source/job/config and reconciled after interruption; independent SDK, Native, kernel and physical-effect evidence also remains open.
