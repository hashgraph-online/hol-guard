# Enterprise evaluation data-boundary inventory

Status: source and synthetic-plugin evidence only. This is a scoped inventory for the local adapters, not a claim that a final model request is redacted. Recheck each row against the installed host and exact release artifact before using it as evaluation evidence.

| Boundary | Current Guard seam | Possible control | Limit and evidence needed |
| --- | --- | --- | --- |
| User prompt submission | Supported host prompt hooks and wrapper screening; see `harness-support.md` and `adapters/contracts.py` | Inspect intent and deny where the host honors its hook | Host/version behavior and downstream side effect need live proof. A prompt hook does not rewrite the model request. Cursor's native prompt submission is not surfaced by the declared contract. |
| Tool arguments before action | Cline AgentPlugin `beforeTool` in `adapters/cline_plugin.py`; native pre-tool hooks on declared hosts; the native MCP relay and the runtime MCP proxy in `proxy/runtime_mcp.py` | Inspect and block at the declared hook/proxy seam | An adapter decision is not proof the host suppressed execution. Use denied and allowed side-effect witnesses. There is no general argument rewrite contract. |
| Sensitive file read through managed MCP | The native MCP relay and `proxy/runtime_mcp.py` score each `tools/call` with the tool-risk categories, including `secret_access`, which match secret-like names such as `.env` or `.ssh` in the tool definition and arguments | Block or review forwarding to that managed MCP server | Only traffic routed through the relay or runtime proxy is covered, and only the risk categories decide it; there is no separate resolved-path check for a file read. The proxy forwards the original message after an allow; its `_redact_json` helper sanitizes event fields, not that forwarded request. |
| Tool result before model delivery | Cline AgentPlugin `afterTool` in `adapters/cline_plugin.py` can replace its result; native Cline `PostToolUse` is observation-only | Replace or withhold the result on the active plugin transport | The plugin now withholds output when review is unavailable and projects allowed, blocked and replaced results to reviewed `output` plus `isError`, dropping unreviewed metadata. `tests/test_cline_hook_transports.py` exercises the generated plugin synthetically; installed Cline and exact model-visible serialization still need live proof. Other native post-tool hooks do not inherit this guarantee. |
| Guard receipt, diagnostics and sync output | `redaction.py`, `secret_redaction.py`, and scoped event sanitizers | Sanitize Guard-owned evidence | These helpers do not establish host payload mutation. Preserve the empty legacy `original_sha256` field to avoid a low-entropy hash oracle. |
| Final serialized model/API request | No general request mediator is declared in the local adapter contract | Unsupported for request-side redaction until a specific host/gateway seam and downstream bytes are proven | Do not infer this from prompt hooks, MCP proxy, Cline tool-result replacement, or sanitized receipts. No universal TLS interception or hidden endpoint substitution is part of this contract. |

Proof levels remain separate: source inspection, unit test, synthetic adapter event, live installed-host test, and independent review. For a block, capture the denied side-effect target and a successful allowed counterpart. For redaction, inspect the complete serialized request at the controlled downstream receiver, including nested fields and metadata; a plugin return value alone is lower-level evidence.
