# Passive Python observer lock boundary

The Rust host reader now has a separate `read_private_jobs_if_idle` entrypoint. It opens the existing private `agent.lock` through no-symlink descriptors, requires the current user's single-link 0600 regular file, and attempts a **nonblocking shared** `flock`. Python's observer holds an exclusive lock while it owns the queue. A busy lock returns `ObserverBusy` immediately; Rust neither waits nor takes over. When the lock is free, Rust retains its descriptor while it reads all bounded private job records, then rechecks the visible lock, `private`, `jobs`, and state-root identities. The result is a read-only idle diagnostic, never admission or snapshot-publication authority.

On 2026-10-20, six local `private_jobs` integration tests passed, including an idle read, exclusive-writer busy refusal, and unsafe mode, hardlink and symlink lock refusals. The uninstalled summary-only `gauntlet-host-shadow-idle` binary was invoked against the retained Mac state at `workflow-benchmark-implementation/.gauntlet-ops`. It exited 2 with `Python observer owns the host state`, as expected while the Python observer was active. It did not stop the observer or read/publish private job contents. A live coherent idle snapshot, intentional interruption, remote receipt reconciliation and Rust observer ownership remain open.
