# Linux ARM64 Rust executable proof

On 2026-10-20, the Rust verifier linked as a static `aarch64-unknown-linux-musl` executable on the Mac host. Its SHA-256 was `a03ab1ecc770ad41df058b8fa7edc9bcb745bf89d79b3ef52d06110fa7b27d1c` on both host and the idle 16-GiB Linux ARM VM. The binary returned exit code 2 for missing required arguments. With the committed signed synthetic complete bundle and separate outside pins, it exited 0 and reported five authenticated files, eight scheduled and eight recorded episodes, `integrity: valid`, `completeness: complete`, `status: exploratory` and `qualification_eligible: false`. This proves the binary linked and the fixture can be read on ARM; it is not a live benchmark or a trusted eligibility decision.

The initial macOS-to-Linux cross-link failed with undefined `ring_core_0_17_14__*` symbols. The `ring` build output showed macOS `ranlib` warning that ELF archive members were not Mach-O. Rebuilding `ring` with target-specific Zig/LLVM `ar` and `ranlib` wrappers, in addition to the existing target C compiler and linker, resolved the link failure. The target archive tools must be specified for any repeat cross-build; using the host archiver can leave an unusable ELF archive index. The ad hoc wrappers live outside this repository and are not a deployable build system.

The isolated `gauntlet-rust-contracts.yml` workflow now also has a native `ubuntu-24.04-arm` job that builds every Rust Gauntlet executable and runs the evidence/worker unit tests from the exact PR head. This avoids the macOS cross-archive issue in CI. Both the `arm64-binaries` and `contracts` jobs succeeded on [PR #5402](https://github.com/hashgraph-online/hol-guard/pull/5402) at `780f2db6995383e442fe4b2f11f450316346521f`. A reviewed immutable release artifact is still open; no worker was installed or launched by this proof.
