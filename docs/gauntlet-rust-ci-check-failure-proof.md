# `ci check` failure projection proof

The Rust evidence crate now projects Python `ci_pipeline.failed(profile, reason, code)` for the four declared `ci check` profiles and the two pre-execution failure codes actually used by the pipeline: `2` (`invalid-evidence`) and `130` (`interrupted`). It retains the six deterministic, twelve beta-E2E, or two feature-AI case IDs in their Python order, marks each cell failed with the same reason, and returns the same selected count and error list. The Rust API wraps that Python-shaped row with `execution_eligible: false`; it refuses unknown profiles, other exit codes and empty or oversized reasons.

Eight expected rows were generated by executing the pinned Python `failed()` function, with SHA-256 pins for `ci_pipeline.py` (`ff3ece762f411439385fff86cc9ac017203f93a0ba0e4e63bae16ceceae2529b`), `beta_profile.py` (`aee91027c178e5538270dbd57265251ee776458125b9879e44ef083e89c30e9b`) and `deterministic.py` (`e819cf846a62506a3b3523f4b6471d3fb5f85c117578fafc5a1746ef925b06ae`). The test independently checks those source bytes before comparing every Rust row to the Python fixture. The generator is `ci/gauntlet-rs/proofs/generate_ci_check_failure_fixtures.py`; the fixture and parity test live under `gauntlet-evidence/tests`.

Both focused tests passed with Rust 1.88 on macOS and offline Linux ARM64. The full Rust workspace passed pinned Rust 1.88 warnings-denied Clippy, and the fixture generator passed focused Ruff. The ARM64 PR workflow now runs this parity test. This covers only the initial failure body: it does not reproduce the final `gauntlet-ci-check.v1` envelope or JUnit artifacts, execute shards, authenticate evidence, or claim a Guard result. The broader `ci check` status/exit and model-backed benchmark exits remain open.
