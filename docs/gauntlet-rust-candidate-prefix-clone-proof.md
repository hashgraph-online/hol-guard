# Inert installed-prefix clone proof

The Rust `gauntlet-candidate-prefix-clone-shadow` diagnostic builds a private, one-use `inert-prefix` under a captured build job. It accepts an outside-pinned, Root-owned baseline prefix and the separately staged wheel tree. Before any write it holds both worker locks, verifies the captured source and archive, confirms that the builder container/profile/cgroup are absent, and hashes both source trees. It copies baseline files and safe symlinks through descriptor-relative paths, omits only the old `codex_plugin_scanner` and `hol_guard-*.dist-info` trees under `lib/python3.12/site-packages`, and overlays the candidate wheel files as data. Each copied file is fsynced and hashed again through a separate read-only descriptor. The new native file receives mode 0755; other wheel files receive mode 0644. The result is a private data tree, never an admitted deployment.

The synthetic ARM Root test passed: a reviewed dependency was preserved, the old product and distribution files were absent, the new wheel files were present, and the native mode was 0755. The diagnostic was cross-built from the locked Rust workspace, installed Root:Root mode 0500 with one link in the 2-vCPU/16-GiB VM, and independently rehashed to SHA-256 `fbb9b8ec86fb42ac0f65aa5fbe1bc8ef80c273aee08917c1a82118be8fb22c33`. Warnings-denied ARM64 Clippy passed. A wrong outside baseline digest refused before the one-use target existed.

The live diagnostic used captured v3.48.0 job `aaabefe820493283`, its 19,739,196-byte archive SHA-256 `a427dad674c9cd0b37ee14b1d72483de6838b1e8fbfe95b224ecd5abd0da3944`, and staged wheel tree SHA-256 `cbafa46e0555764406450a1c5940a69c781352f4dfcfb932259396a19c8a387c`. The reviewed 3.49.0 baseline prefix had 5,640 entries, 123,171,929 bytes and independently pinned tree SHA-256 `9af26c159ba48f4ab3f5b4535cd1e146b3c097560a1c4434f8703e508b5786c8` before cloning. The Rust result had 5,585 entries, 120,610,680 bytes, 1,706 wheel files and tree SHA-256 `b25a0f04235238e3cd5b64df04dc4fa8fd7f82b2aca7142d46336ca63330fa1e`.

The pinned Python `runtime_bundle.inventory` independently read the Rust tree and returned the same entry count, byte count and digest. The trusted Python `clone_with_wheel` routine then copied the same baseline and staged wheel files into a separate private target; its independently inventoried tree had **the identical** 5,585 entries, 120,610,680 bytes and digest `b25a0f04235238e3cd5b64df04dc4fa8fd7f82b2aca7142d46336ca63330fa1e`. Root metadata inspection confirmed the 28,814,776-byte native file was mode 0755 with one link; the old `hol_guard-3.49.0.dist-info` path was absent and the new 3.48.0 metadata was present. A replay refused, and the Rust tree digest remained unchanged.

This proves a source-bound inert prefix clone and byte-for-byte parity with Python's clone routine on one retained release wheel. It does not validate new dependency requirements, create a config or signed conformance package, invoke feature audits, run deterministic controls or call a model. Both the wheel and cloned prefix remain `artifact_admitted:false` and `execution_eligible:false`.
