# Read-only VM source archive proof

`VmSourceArchiveProbePlan` derives the one fixed guest inbox path from the validated operations config and a lowercase 16-hex job ID. It invokes bounded `limactl shell` with an isolated fixed Python probe, no shell interpolation or arbitrary guest command. The guest opens the existing archive with `O_NOFOLLOW`, requires a regular single-link mode-0600 file below 256 MiB, hashes its bytes, and compares inode, size and timestamps before reporting a small JSON row. The Rust host rejects malformed, duplicate-key, oversized, wrong-digest or unsafe-metadata responses and always reports `execution_eligible: false`. The uninstalled `gauntlet-host-shadow-vm-source` command exposes this read-only check.

Three Rust tests passed on macOS and Linux ARM64: the fixed plan and valid projection, wrong digest or unsafe guest metadata, and arbitrary job/oversized response refusal. Warnings-denied native host and ARM64 workspace Clippy passed. On 2026-10-21, the live Lima probe read retained v3.48.0 job `7b3dd7131df5fedd` in `hol-beta-bootstrap-20261016-004`. It observed 44,902,294 bytes, owner UID 501, mode 0600 and SHA-256 `5d3eeff80bedd07042a28ffdf5d0192500669b238384ca71f7a3f8631f9382be`, matching the previously recorded host archive pin. No archive was copied, removed, staged or built during this probe.

The outside digest was recorded from the retained host job, not independently reviewed. This proves the observed guest file matched that digest at one point in time. It does not implement a Rust copy, authenticate Lima or the guest executable, bind the later Root build capture to the same inode, or authorize a benchmark result. The Python observer and VM builder remain authoritative.
