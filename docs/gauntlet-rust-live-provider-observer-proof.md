# Read-only Rust observation of local model-provider preflight

The uninstalled `gauntlet-host-provider-preflight-shadow` reads the fixed provider template binding and allowance through descriptor-relative no-symlink paths, requires regular single-link files, enforces 64-KiB limits and exact SHA-256 bytes, then parses duplicate-free JSON. It reads the retained Python lifetime quota under the template's pinned config and allowance digests, samples the fixed local port 8002 and applies the [22-case Python-matched Rust preflight](gauntlet-rust-live-provider-preflight-proof.md). Its output always sets `execution_eligible:false`; it never creates a provider directory, reserves tokens, starts MLX or changes the Python observer.

A local macOS build of the diagnostic had SHA-256 `f15ba5e92c83d92d4dd5475e5ef302b33551826d3522cb42c40930f96c23b878`. With a nonauthorized requested Git source `b3d4b93cdb3539554b4830c58df64d33826a9159`, it refused the source before reading either provider input. With the retained historical allowance source `c1d18f931eaba02a37a2c9515db769fc2219bee8`, it observed `known_tokens_before: 13746906` and a 200,000-token `feature-ai` reservation as arithmetically acceptable at that instant; the 1,200,000-token `beta-e2e` reservation refused for insufficient settled quota. All three reports were execution-ineligible. The two Rust reader tests passed on macOS and Linux ARM64 Rust 1.88, including wrong digest, file/ancestor symlink, hardlink, duplicate-key and oversize refusals. Local warnings-denied Clippy passed.

The supplied requested source still needs a trusted caller to bind it to a real candidate. Port availability is a point-in-time observation. The allowance is for the historical source and cannot authorize a new product commit. No inference, live quota reservation or Rust-owned provider process was performed.
