# Fixed-value checks for retained staging effects

The prior Root-owned physical-file reader checked file metadata, bytes and signed-record equality, but accepted the controller's own `node_runtime_closure_control` and `native_contained_boundary_negatives` values as the expected JSON. This change adds an independent expectation before comparing each file to the record. For success, input-binding and injection, the Node result must contain exactly four fields: the private-cell script's fixed Node/npm versions, a regular (not symlinked) Node executable, and the Node SHA-256 from the separately pinned v7 config. For boundary, the eight rows must name exactly the three run-derived canary paths with read/write operations and the IPv4/IPv6 network families, report denial, and use an allowed Linux denial errno. Missing, extra, reordered or changed rows refuse.

The reader now emits `hol-gauntlet-staging-physical-files-shadow.v3` with role-specific `node_runtime_fixed_values_checked` and `boundary_fixed_denials_checked` flags. Two Linux unit tests passed, including a forged Node value that matched a rewritten file but differed from the outside config, and changed boundary path, denial and errno cases. The full Linux evidence library passed 50 tests and warnings-denied Linux Clippy and Rustfmt passed.

The final Linux ARM64 physical reader (SHA-256 `9eadea2405a5e0fa8b5d2bf0c1ad378af7cba28c4859e62eb2359d6b4ab8dbb3`) accepted the fresh `success` role `ab1d121722b9fb44` with five files and the `boundary` role `9751351fc0a98886` with eight files, each returning v3 and its applicable role flag. The final six-role suite reader (SHA-256 `fe2318e43402ea765dcfd1e749dbe8fb19b8f36a8b928dff8bcf47286436e498`) reopened the same outside-pinned manifest `3bbc690ddad204409f17f33a5538291c8262e9e6464c9d81a2c8ca613eeceb2e` and all six tap digests. It matched 144 frames, 32 physical files, five absent effects, six signed records and six cleanup journals, with `outside_cgroups_absent:true` and `execution_eligible:false`.

The fixed values are bound to this pinned staging private-cell source. The file read is after the run: it cannot prove which process wrote the files, whether a particular Native frame caused them, or that Guard made a correct decision. The suite still returns `independent_kernel_sdk_effects_verified:false`, `conformance_package_created:false` and `execution_eligible:false`; the physical-effect parent exit remains open.
