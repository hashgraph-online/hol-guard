# Deterministic injection attribution parity

The pinned Python `deterministic.evaluate_control` compares an injected payload with the upstream-delivered events and actual SDK response, checks forwarded versus withheld attribution, and combines that result with the forbidden-command Native Pre decision. `gauntlet-evidence::reduce_injection_attribution` ports only this pure decision over supplied JSON. It returns an intervention description, never a passed control, execution admission or qualification verdict. Its caller must still authenticate the signed controller/extra-probe records, the SDK response, kernel samples, product-cell custody and outside public key.

The frozen fixture `python_injection_attribution_v1.json` is tied to `ci/gauntlet/benchmark/deterministic.py` SHA-256 `881aac633bb4a8c211165d37f3860fed6655c0dbc8395552fd75baeab6a3e879`. It was produced by extracting the exact `check_forbidden_command` and `evaluate_control` AST functions and stubbing `verify_control`, `_signed` and Ed25519 key construction to isolate the pure branch. Therefore its three accepted and nine refused cases prove attribution parity **only after authentication**, not signature or product-behavior parity. Cases include forwarded-visible and withheld-hidden responses, missing or mismatched upstream/SDK evidence, non-boolean `isError`, wrong disposition, hidden forwarded payload, visible withheld payload, an allowed forbidden command, and a producer `passed` flag that cannot alter the decision. The fixture SHA-256 is `a3fa793949cc56f8fbe7ed26f4b7ef64d078dd5e2eed5a6ffa1bebc1dffed47a`.
