# Action explanation runtime and persistence

Everyday Mode explanations are generated by HOL Guard Core from authoritative typed action data. They are presentation artifacts, not enforcement inputs.

## Build boundary

`runtime/action_explanation_builder.py` consumes a typed action envelope, the existing `CanonicalCommand` when one already exists, extension/risk observations, and decision context. The decision contributes reason/outcome context only. It never changes action parsing. The builder is deterministic, bounded, side-effect free, and has no network, subprocess, socket, or model dependency.

A semantic-fact layer sits between Core action data and rendered prose. This keeps action identity, canonical command identity, targets, source/sink facts, extension IDs, rule IDs, confidence, and retention state separate from localized text.

## Identity

Every explanation is bound to its approval/receipt action identity. Command explanations are also bound to the canonical command security identity. Consumers reject an action or canonical identity mismatch and may reject a catalog-digest mismatch. Cache identities cover action identity, canonical identity, semantic catalog digest, renderer version, locale, and redaction version.

## Projections

The full in-memory contract can contain an authorized technical projection. The default list projection strips command text, normalized command text, arguments, segments, and working scope. The Cloud-safe projection is a strict safe subset and does not include raw prompts, raw shell text, environment values, full local paths, or secret-like arguments.

Technical content is populated only when it was retained and the caller is authorized. If it was not retained, the projection keeps `unavailable_reason=not_retained`; changing presentation mode never reconstructs omitted content. If it exists but the current surface is not authorized, the projection keeps `unavailable_reason=not_authorized`.

## Redaction and deletion

All technical display variables use Guard's existing redaction service before they enter an explanation. Persisted safe projections carry the redaction policy version plus omitted/truncated/secret-removal metadata. Deleting or expiring an underlying receipt or action must not leave an independently recoverable raw action in an Everyday projection. Safe projections may persist the action identity, canonical identity, safe headline/summary IDs and text, typed target labels, consequences, safer alternatives, confidence, catalog digest, and redaction metadata according to the owning receipt/history retention policy.

Mode changes affect disclosure only. They do not extend receipt retention, resurrect deleted technical evidence, or re-run the action parser against UI strings.
