# Signed control session and SDK-gate opening

The Rust `verify_control_session_opening` continues the signed deterministic-control reader through Python `local_executor_controls.verify_control` statements `body[1:28]`. It verifies the outer controller-signed runtime and nested builtin records against an outside public key, binds the declared controller session to the task allocation, requires the checkout/remote/home source paths, and carries the reported pre-import SDK gate fields forward. It returns data for later custody checks and never returns a Guard pass verdict.

It signed synthetic runtime and builtin records, without importing the controller, SDK or product. Nine cases refuse wrong session, traversal, checkout/provider paths, incomplete SDK cleanup, SDK error, unauthenticated peer flag or post-import binding, with the exact Python reason strings.

A separate stripped, SHA-matched ARM64 test binary (`7c0c6f9ba83c4fdc177644cded07af4fda5f81fcf02ba927fc2cd614dc72c45b`) passed on the idle VM.
