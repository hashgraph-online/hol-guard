# One-use Rust shadow candidate assets

`gauntlet-candidate-shadow-assets` copies a previously captured candidate's inert data into a new Root-owned `/opt/hol-gauntlet/rust-shadow-candidates/<job>` tree. It holds the Rust active lease and Python worker lock, requires the build container/profile/cgroup to be absent, checks the captured source and archive against outside pins, inspects the complete nested wheel and actual native bytes, and requires the existing inert prefix to match its outside tree digest and installed Guard metadata. It enforces the 8-GiB VM free-disk floor plus the estimated copy and a 64-MiB margin **before** creating the shadow destination. A destination is exclusive and retained on failure; the same job ID cannot be retried.

The copy uses descriptor-relative no-follow reads and exclusive writes. It preserves every prefix entry, including the candidate product, with the same bounded copier used for the prior baseline clone. Every copied file is fsynced and independently read back, then the copied prefix is inventoried against the outside digest. The wheel and native files are independently written and read back with mode 0444 and 0555. The shadow root stays Root-only mode 0700. No candidate interpreter, installer, hook or model runs, and no config or deployment is written.

The static ARM64 binary had matching host/VM SHA-256 `d3b94870de3446a77aa059177d21c3847df1f9693c440f3ed8ad67c9d724d66a` after installation as Root:Root mode 0500 with one link. An unprivileged invocation refused. A wrong outside prefix digest refused before `/opt/hol-gauntlet/rust-shadow-candidates` existed. The exact-pins run for v3.48.0 build job `aaabefe820493283`, source `3864097f2e4fe623e403c1a948d9882f34c78690`, copied 5,585 prefix entries and 120,610,680 file bytes. Rust returned prefix digest `b25a0f04235238e3cd5b64df04dc4fa8fd7f82b2aca7142d46336ca63330fa1e`, wheel digest `f26789b61b00b115c5506ea75900e70dcbcbda353467b4d3fcfa183c886f94ba`, and native digest `f92d6c007ddbf49ef00d547a72a6ba8dfacf6f98db2150177c2baf41cb944311`.

The pinned Python `root_prefix_inventory` and `runtime_bundle.inventory` separately read the new shadow tree and agreed on digest `b25a0f04235238e3cd5b64df04dc4fa8fd7f82b2aca7142d46336ca63330fa1e`, 5,586 entries **including the root**, and 120,610,680 file bytes. Independent Python SHA-256 reads matched the wheel and native digests; both had one link and the expected modes. A second exact Rust invocation refused with `one-use shadow asset root already exists`, and a later Python inventory found the same prefix digest. The VM had 11,517,722,624 free disk bytes afterward, above the 8-GiB floor. Warnings-denied ARM64 Clippy and the native workspace suite passed before this copy.

The asset tree is deliberately separate from the Python candidate path and is not admitted. Its private parent prevents unprivileged use. A [later source-matched private-cell and one-use config proof](gauntlet-rust-candidate-shadow-private-cell-proof.md) completed the inert config/asset readback; fresh signed conformance and installed deterministic controls remain open. This asset-copy proof alone does not establish those exits.
