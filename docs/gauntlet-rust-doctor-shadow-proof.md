# Read-only Rust doctor shadow proof

`gauntlet-host-shadow-doctor ABSOLUTE_STATE_DIRECTORY` composes the existing owner-only operations reader, native host telemetry, fixed read-only Lima VM probe, exact release-tag Git lookups, and Python-compatible resource-admission reason calculation. It requires the passive release-tag/local-VM mode. Each probe has a bounded command, output and deadline; a failed host, VM or release lookup reports unavailable/disconnected rather than silently appearing healthy. It takes no observer or worker lease, writes no status file and always emits `execution_eligible: false`.

On 2026-10-21, the uninstalled macOS command read the existing host state and reported the running `hol-beta-bootstrap-20261016-004` VM with two CPUs, 16,733,863,936 bytes total memory, 16,151,953,408 bytes available memory, 48,803,864,576 bytes total disk and 14,886,461,440 bytes free disk. The host sample had 32 CPUs and 331,605,606,400 free disk bytes. Its fixed Git lookups resolved `v3.48.0` to `3864097f2e4fe623e403c1a948d9882f34c78690` and `v3.49.0` to `e3f9e7eb4e0cc7b1987780a62697e8bb221ae050`. `admission_reasons` was empty and `resource_healthy` was true. Warnings-denied native host Clippy passed for the composed binary; the component probes and refusal classes had passed their earlier macOS/ARM64 tests.

These are point-in-time resource and tag observations. They do not attest the Git executable or source host, reserve an admission slot, verify a current controller deployment, run six controls, prove model inference, or give Rust ownership of the Python observer. An empty resource-reason list is not a full benchmark admission decision.
