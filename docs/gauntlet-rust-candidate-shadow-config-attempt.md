The Rust shadow config writer projected the captured v3.48.0 release candidate from the installed v7 template into the separate Root-only asset root for build job `aaabefe820493283`. It wrote `/opt/hol-gauntlet/rust-shadow-candidates/aaabefe820493283/provisional.json` once, as a Root-owned ordinary file with mode 0444 and one link. Its file SHA-256 was `6303e117c04310751fb917c5ecf69066a3a15db94c8e7c32fce75ca5d2e57f62`; its 8,888 canonical bytes had digest `41b7349fb0054e51abfaf25ef69202cc2377b1539428a08f713be3d8999fe4cb`. An independent pinned Python projection produced those same bytes and digest. The writer returned exit 2 after the write, so the one-use file remains retained and is not a successful asset-verification proof.

The old installed Python reader and an older Rust verifier both accepted the 13 file/tree assets. A Rust verifier built from the **current branch** refused the config with `private-cell bootstrap differs from controller source`. Its static ARM64 binary SHA-256 was `dfce9b22db8bf94da6d792e02322506170bc09d629effab02bd43d4d11b35a05`. The refusal is correct: the template points to the VM's previous private-cell manifest, whose supervisor digest predates the current Rust worker's embedded 36-file controller source map (`909592fac5403f683df5673f5f195eac014986e91d50e547b7c214871507ae54`). Python validation from that **older installed controller** cannot qualify the current Rust generation.

The config writer now reports separately whether loading the declaration or verifying assets failed, including the underlying reason on its Root-only diagnostic channel.
