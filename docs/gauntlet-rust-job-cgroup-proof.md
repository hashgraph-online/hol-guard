# Job-derived controller cgroup probe

The Rust launch plan now derives two separate kernel locations from the parsed 16-lowercase-hex job ID: `/<holgauntletrust...slice>` for systemd-managed product cells, and `/system.slice/hol-gauntlet-rust-job-<job-id>` for a future directly contained controller. The cgroup name is not accepted from a request. An inert Root-only probe reuses the fixed cgroup containment path with the job-derived name; it creates the group exclusively, applies the probe's 512-MiB memory, 16-PID and one-CPU limits, starts only `/bin/sh` with an `/usr/bin/sleep` grandchild, writes `cgroup.kill`, checks recursive drain and removes the group. Any pre-existing or changed group remains unknown rather than being replaced. These limits are **probe settings**, not a reviewed production benchmark budget.

On the idle 16-GiB `hol-beta-bootstrap-20261016-004` VM, the final stripped ARM64 probe had SHA-256 `2d83369c4a640943d186bb29bbf07a202f55d53e2d15f27d33adb3128de19a76` on host and guest (725,704 bytes). An unprivileged invocation refused. The Root run observed two tasks in `/system.slice/hol-gauntlet-rust-job-0123456789abcdef`, reported recursive kill, drain and removal, and explicitly reported `controller_executed:false` and `execution_eligible:false`. A separate `stat` found that exact cgroup path absent afterward. The stripped ARM64 worker-state test binary from the same source before the shared-name alignment (`2d8c514fcad32321431ba313138a874fc14e8aeba9c4c5ebac62f4cc8aaaa9c6`) passed all 25 Linux unit tests on the VM. The name-aligned source also passed the targeted ARM container test and Mac launch-plan parity tests. All temporary VM binaries were removed; root filesystem free space returned to 8,660,406,272 bytes, above the 8-GiB floor.

This proves only inert per-job cgroup creation, containment and cleanup. No controller, candidate product, benchmark or model was executed. A production worker still needs reviewed per-job resource limits, an exclusive lease and durable reservation, descriptor-bound Root-owned controller/interpreter launch into this cgroup, fresh PID/start-tick/cgroup observation, a bounded deadline, process reaping, the separate product-slice stop/absence proof, authenticated report scoring and recovery after interruption.
