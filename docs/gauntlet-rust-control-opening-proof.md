# Deterministic control opening parity

`gauntlet-evidence::verify_control_opening` ports the opening segment of Python `local_executor_controls.verify_control`. It requires exact completed/SDK/no-model/no-Root-import claims, absence of error fields, explicit cleanup claims, a controller key matching an outside 32-byte Ed25519 pin, signed `developer_runtime` and nested `native_builtin_audit` envelopes, exact outside conformance tuple and private-cell backend fields, current completion/output profile names, and equality between the detached and signed product plane. It returns the signed runtime and builtin records for later checks. It does **not** authenticate the outer SDK result, kernel/process observations, Native Pre/Post review, product-cell cleanup or model behavior, and returns no pass verdict.

The reproducible generator `ci/gauntlet-rs/proofs/generate_control_opening_vectors.py` extracted `verify_control` statements `body[1:17]` from Python source SHA-256 `22773101b8880d65dd85183a4212ca8efa57897388ad1408ab5d1ad971111427` and the exact `_require`/`_signed` functions from custody source SHA-256 `fa347e8cf791c21a4ce6de8d331bfbb80d80f605d0e927f672ed8475e24de21e`. It executed those statements only against deterministic synthetic records signed with Python `cryptography` 41.0.7 on the ARM VM. It used the Python canonical JSON representation for these small fixtures and did not import or run the product or controller. The frozen fixture `python_control_opening_v1.json` has SHA-256 `0209519bcb9a9178a5b81ce7af309c554b1ae04d7503865d5615f3d3a0ae0a90`.

Rust matches all 23 Python cases: four accepted signed openings, including the v4 branch without package version, and 19 refusals covering role, execution and cleanup claims, outside key, both signatures, source/version/private-cell tuple pins, profile/schema, and a detached plane. Separate Rust tests refuse duplicate outer JSON and treat a boolean removal return code as invalid rather than equating `false` with zero as Python does. That extra refusal is a deliberate fail-closed difference. The remaining Python session/path, pre-import SDK binding, private-cell runtime, Native review, provider/output, boundary and cancellation checks are still unported.

The full local Rust workspace suite with all features, formatting and Clippy with warnings denied passed. After adding the v4 fixture, the focused tests passed locally and in the Linux ARM container; ARM Clippy also passed on the unchanged library. The final stripped ARM test binary with SHA-256 `549f7b3efeec6ead8c822b94a4eed84fa24d0b6d21a683b31fe3b1ff68c7025a` matched on the host and retained VM, passed all four tests unprivileged there, and was removed. No controller job or model request ran.
