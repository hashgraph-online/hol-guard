# Rust release queue decision proof

The passive `gauntlet-host-state` crate ports the data-only release queue decisions from the pinned Python controller. It parses the two queue fields from an already trusted operations document, decides whether a job is admitted, reduces unwatched jobs in memory, and selects the first queued candidate after the Python observer's hold/active/admission/unknown checks. No function reads GitHub, takes an observer lease, starts a VM job, writes a journal, posts a PR status, or publishes a dashboard snapshot.

The fixture generator `ci/gauntlet-rs/proofs/freeze_release_queue_v1.py` refuses to run unless `releases.py` has SHA-256 `de558acc1946900d587d2624bfa4128468d649d6bf158f71b628e44dac4598e6` and `agent.py` has SHA-256 `04aed1ecf337746caed8fbd011c59926b47b37719add867628ac6b70a5309215`. It calls the actual Python `admitted` and `archive_unwatched` functions with a fixed clock. The selection vector transcribes the pinned `Agent.run` predicate and order; the whole owning source is hash-pinned. The fixture has 30 admission outcomes across both discovery modes, two 13-job archive passes, and 10 queue-selection cases. It covers exactly v3.48.0/v3.49.0 admission, other releases, operator-queued local candidates, archived records, publish/source errors, hold/resource/active blocks, terminal states, and an archived `unknown` job that still blocks selection.

The four Rust integration tests compare the outcomes and full post-archive job values with the Python fixture. They also check malformed configuration and job batches fail without partial in-memory archive. Local `cargo test -p gauntlet-host-state --locked` and `cargo clippy -p gauntlet-host-state --all-targets --locked -- -D warnings` passed on 2026-10-20. The isolated workflow additionally runs the fixture test on native Linux ARM64 after this change reaches the PR head.

This is only a pure state reducer. It has no trusted input reader, exclusive host lease, exact-tag GitHub source recheck, persistent state migration, observer restart/reconciliation, or live VM dispatch. The current Python release observer remains authoritative. The host queue parent exit in the execution checklist stays open.
