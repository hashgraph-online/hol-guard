# Isolated Rust controller installation on the ARM VM

The uninstalled Linux ARM64 `gauntlet-controller-install-shadow` is a Root-only installer for a **new** fixed `/opt/hol-gauntlet/controller-<commit-prefix>` directory. It accepts a transferred source root, a full commit SHA, a bounded path-to-SHA-256 map, and an expected whole-tree digest. Rust reads all listed source files through no-symlink descriptors, checks their bytes and stable file identity, and holds the validated bytes before writing anything. It derives the pinned Python bootstrap's file selection and modes, writes into an exclusively created `.partial` directory, verifies the complete Root-owned tree, then uses non-replacing rename and verifies the final tree again. Existing controller generations are never overwritten. An uncertain partial is retained for inspection. The result always says `controller_executed: false` and `execution_eligible: false`.

On 2026-10-20, a fixed Linux ARM64 build first installed the 426-file integration map into an ephemeral container's isolated `/opt/hol-gauntlet` tmpfs. It selected 395 files and returned controller digest `a62dd6dd884448f83f612c4895648577ea66e18c720942b3b7ca3a707894170e`. A wrong tree digest refused before writing. Altering the hash of the excluded `control_plane/bootstrap.py` source file also refused, proving the installer checks all 426 transferred inputs, not just the selected files. Linux ARM64 Clippy passed with warnings denied.

The same source bytes were packaged from exact Git commit `73b1ed869d8a3c98155d7f8bc820c3f6971aeec3` in a 4,249,600-byte tar archive. Every regular tar member matched the integration map before transfer. The archive SHA-256 `3f8b759a61b7ab04662aca9a39403ad1d375ca4d7159ea490c9fa3998e1b5f1d`, map SHA-256 `e8c35ce2e26ef319c6a28b403afa7c9ad472247ae54d56636f654606bd42aabf`, and installer binary SHA-256 `3b491b3d468d8fb4c8bf21e63770edc8079480e962a5bc983496e20efc4af23c` matched on the Mac and idle `hol-beta-bootstrap-20261016-004` VM. A wrong digest refused there before installation. The positive Root invocation read 3,918,402 source bytes, installed 395 files at `/opt/hol-gauntlet/controller-73b1ed869d8a3c98`, and verified the expected tree. The `.partial` path was absent afterward.

A separate SHA-matched ARM64 read-only verifier (`d584a2f3fdc0ab90fdd0aa82a9f25fa14de5b6e9089161b33a5453d011fa45bb`) then ran unprivileged against the retained tree. It observed 406 entries, 3,635,364 file bytes, Root ownership, fixed modes, and the same digest; a wrong tree pin exited 2. The temporary guest tar, map, binaries and extracted source were removed. The new inert controller tree remains for later review; VM free space was 8,665,169,920 bytes after cleanup, about 4.6 MB below its pre-install value.

This is an isolated source/install custody proof, not a reviewed execution generation. The diagnostic executable was launched from a guest-user-owned temporary path after a SHA comparison; that is not immutable executable attestation or a production Root launch procedure. The map, commit, installer binary and tree digest still require independent trusted-base review and authenticated delivery to the worker. No deployment declaration points to the new tree, no controller code ran from it, and no benchmark, Guard control or model inference was executed. The production worker must bind this installed tree and a reviewed interpreter to a one-time contained child, authenticate its report and cleanup, and prove cutover before it may grant execution eligibility.

This proof predates the optional Rust-owned [product-cell slice change](gauntlet-rust-job-slice-proof.md). The retained directory still proves the non-replacing installer mechanism, but its old digest no longer matches the current integration source map. A fresh reviewed generation is required for live dispatch.
