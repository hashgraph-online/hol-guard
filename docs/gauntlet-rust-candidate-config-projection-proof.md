# Provisional candidate-config projection proof

The pure Rust `project_candidate_config_ineligible` function reproduces the data edits in the pinned Python `stage_candidate.py` for a normal PR candidate after wheel and prefix staging. It requires an outside-pinned, schema-valid v7 runner template and exact source, package, native, prefix and wheel identities. It derives only the fixed `pr-<source>` id and `hol-gauntlet/candidates/<source>/` paths, then updates the Guard source/version, private-cell native and runtime tree digests, and the `guard_prefix`, `wheel`, `native` and `compiler` assets. It validates the projected declaration and returns canonical JSON, the newline-terminated provisional file bytes and the canonical digest. It opens no candidate file and writes no deployment.

Python computes the prefix asset digest through `root_prefix_inventory` and the private runtime digest through `runtime_bundle.inventory`; the latter's `_manifest` deliberately reduces its richer entry rows to the former's digest shape. Rust now accepts these as separately named outside pins and refuses a disagreement before projection. The pinned Python fixture still yields the same 3,673 canonical bytes and `d2ada18656a9a8c51162d376ab24cd80e601b80240641495cfa3710f7a90ae31` digest. On the retained v3.48.0 inert prefix in build job `aaabefe820493283`, both trusted Python readers independently returned `b25a0f04235238e3cd5b64df04dc4fa8fd7f82b2aca7142d46336ca63330fa1e`, 5,586 entries and 120,610,680 file bytes. The CLI now requires both outside values; this check does not authenticate either pin by itself.

The input is the Python-validated v7 fixture at `ci/gauntlet-rs/crates/gauntlet-contracts/tests/fixtures/runner_config_v7.json`, whose outside canonical digest is `580c94be23f58345bf7c59eb11239ae9bd21347b70fadb6c19f243b7f7a3f1e8`. With a frozen 40-hex source, v3.48.0 and separate 64-hex native/prefix/wheel values, the pinned Python JSON canonicalizer produced 3,673 canonical bytes and digest `d2ada18656a9a8c51162d376ab24cd80e601b80240641495cfa3710f7a90ae31`. Rust produced the same length and digest; wrong template hash, malformed source and valid-but-older v6 template refused. Native tests and warnings-denied ARM64 Clippy passed.

The final installed-template diagnostic was cross-built as a static ARM64 binary and independently SHA-matched on the VM at `5746b7b8d4e73f2593f60b5e52450ca16f617cdddb7658832ca57cef6fc77454`, Root:Root mode 0500 with one link. It read the fixed Root-owned `controller-01abe774177c980b/staging-template.json` through stable no-symlink descriptors and checked that the visible controller directory and file had not been replaced. It required raw SHA-256 `45e0fc8a67ecae0a71244a1b1abd3adc37b5d613a5ac177d1cb21ad8737a98d7` and canonical SHA-256 `1923bbea94622590b64f9068c1b8d9e6bc446b11373e0a17cabbaf8b1d72801a`; a wrong raw pin refused in the preceding build. With the independently recorded v3.48.0 release source, native, prefix and wheel digests, Rust projected 8,910 canonical bytes, 8,911 file bytes and digest `7b76199a14d7cb51e03f4a4f49aaa0d5ba7daa71482870e3113e56c36826837f`. The pinned Python `json_data` canonicalizer, run separately on that installed template with the same inputs, returned the identical lengths and digest.

This is parity for an inert transformation of a frozen fixture and the live installed template. The cloned VM prefix remains outside `/opt/hol-gauntlet/candidates`, and the live reader accepts outside native/prefix/wheel pins without re-inventorying those assets. No candidate provisional config has been written or admitted. Full `load_config`, asset verification, fresh signed conformance, final config and deployment creation remain open.

The follow-on `gauntlet-candidate-config-artifacts-shadow` reader holds the Rust active lease and Python worker lock while it binds this same projection to captured job `aaabefe820493283`. It checks the fixed source archive and captured candidate archive against outside digests; inspects every nested wheel entry and its native bytes; inventories the Root-owned inert prefix twice; compares installed Guard source/version/native manifest fields; and hashes the actual installed native file. It reads the separately pinned installed template, then rechecks source, archive, prefix, inactive build state and both locks. The static ARM64 binary had matching host/VM SHA-256 `150284c9aa38012ac5d8867ecc7e995a7f847a2fc0cad3f333e83df5e19326a6`, was installed Root:Root mode 0500 with one link, and returned the same 8,910-byte config digest `7b76199a14d7cb51e03f4a4f49aaa0d5ba7daa71482870e3113e56c36826837f`. Unprivileged execution refused; wrong outside wheel and prefix digests separately refused. ARM64 compilation and warnings-denied Clippy passed. This binds the **data projection** to retained inert assets, but it still writes no config, has no independent conformance, and cannot admit execution.
