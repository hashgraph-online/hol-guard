# Descriptor-bound interpreter in an isolated ARM cgroup

The uninstalled `gauntlet-contained-interpreter-shadow` joins two previously separate Rust proofs on Linux ARM64. It reads the retained deployment and holds its already-hashed Root-owned Python executable descriptor. A fixed Root-only cgroup is created with 512 MiB memory, 16 PID and one CPU limits. In the child, a `pre_exec` callback enters that cgroup, sets no-new-privileges, clears supplementary groups, drops real/effective/saved UID and GID to 65534, and calls `execveat(AT_EMPTY_PATH)` on the held executable. The fixed `-I -S -B -c` Python snippet forks once and sleeps; `-S` disables `site` imports. No controller module, candidate, Guard control, benchmark or model is invoked. The parent requires two tasks, reads the child UID, `NoNewPrivs`, and zero permitted/effective/ambient capabilities from `/proc/<pid>/status`, writes `cgroup.kill`, reaps the child within a fixed wait with direct-kill fallback, confirms recursive drain, removes the cgroup and rechecks the held executable. All outputs remain `execution_eligible: false`.

On 2026-10-20, the final Linux ARM64 diagnostic binary had SHA-256 `e7f83636cedd41f92b2e9035a70791bdd7a5b58d0b6ebd220e12d8eff7754e1e` on the Mac and on the idle `hol-beta-bootstrap-20261016-004` VM. It was copied to a temporary guest path, installed mode 0500 under a new Root-only diagnostics directory, and rehashed there before Root launch. Against the retained source `b4efd8171b06d0e13cbe12a077c376ecdc891fd1`, raw deployment digest `e65ab14fb8cb3d4ecb5f5eec3ff96170b2d6efd24c51e5a14d428e4427011e36` and interpreter digest `c86f21d0da9290ece2d7d49a3f7ed52aed59cb029abdf0ea25c79634f6cbe960`, it observed two cgroup tasks, child UID 65534, `NoNewPrivs: 1`, zero permitted/effective/ambient capabilities, recursive kill, drain and removal. An unprivileged invocation and a wrong interpreter digest of the preceding build both exited 2 before creating a cgroup; the final change only bounds the reap path. The diagnostic and temporary files were removed afterward; the fixed cgroup and diagnostics directory were absent. VM free disk was 8,665,001,984 bytes after cleanup.

The SHA-matched stripped ARM64 worker-state test binary `872f47f19b222d0c662c7e5650fad910bbc3fab95cc8e7d9b16c97bb26b1ffec` passed all 19 library tests in the VM, including a three-second direct-kill/reap fallback for a fixed 30-second child. Final ARM64 Clippy passed with warnings denied. Three self-cgroup tests failed in an ordinary Docker container because its process is placed at cgroup `/`; the same binary passed all 19 on the Lima VM's real non-root cgroup path. The tests do not represent a fresh benchmark job.

The supplied deployment and interpreter hashes were observed on the retained VM rather than authenticated from a reviewed release generation. This proof does not bind the newly installed controller generation, a one-time job marker, authenticated report, model provider, product isolation, or scoring to the child. The old Python observer and release gate remain authoritative and passive respectively.
